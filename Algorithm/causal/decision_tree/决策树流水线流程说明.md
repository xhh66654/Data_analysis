# 决策树离线流水线流程说明

## 轨迹数据接入与预处理

系统首先接收由仿真或专家飞行导出的离线轨迹数据，通常以 CSV 形式存储，每一行对应一次控制决策时刻。数据包含当前八维状态特征（s_0 至 s_7）、下一时刻状态、实际执行动作（action）、即时奖励（reward）、回合编号（episode）以及终止标志（dw、truncated）等字段。系统对数据进行完整性校验与数值清洗，确保状态、动作与奖励不存在缺失或非法值，并据此构造供后续价值学习使用的状态转移样本。该阶段不生成策略规则，但直接决定后续全链路分析的样本规模、动作分布与数据质量上限；若输入数据存在缺失、噪声或样本量不足，将限制后续 Q 估计与决策树泛化能力。本步完成后，轨迹表与转移构造结果进入内存，为 FQE 提供训练样本，并为决策树阶段提供「状态 → 动作」一一对应的标签来源。

## FQE 价值网络训练（Q_hat）

在数据预处理完成后，系统引入 FQE（Fitted Q Evaluation，拟合 Q 评估）方法，利用神经网络对「在给定状态下执行某一动作的长期价值」进行离线估计，得到价值函数近似 Q_hat(s,a)，并保存为 q_hat.pt。训练过程中，系统以轨迹中的状态、动作、奖励及下一状态信息为输入，通过 Bellman 自举方式不断更新网络参数，使其逐步逼近行为策略下的长期回报水平。该网络本身不直接参与在线决策，也不生成新的飞行轨迹，而是作为后续步骤的「价值评估器」，用于衡量每一步实际动作与价值意义下较优动作之间的差距。FQE 训练是否稳定、loss 是否收敛，将直接影响后续 l_hat 与 weights 的可信度，进而影响 VIPER 抽样重点是否合理；Q 估计越准确，后续越能识别出真正值得重点学习的关键决策时刻。本步输出 q_hat.pt 及训练损失等元数据，不直接产生 IF-THEN 规则，但为整条链路的加权模仿提供价值标尺。

## 逐步价值差距计算（l_hat）

在 Q 网络训练完成并冻结参数后，系统对轨迹中每一行样本进行逐行评估，计算该时刻实际动作相对于价值最优动作的差距，记为 l_hat。具体而言，系统首先根据当前状态得到所有候选动作的 Q 值，取其中最大值作为 V_hat，再读取该时刻实际执行动作对应的 Q 值 Q_sa，二者之差即为 l_hat = V_hat − Q_sa。l_hat 越大，表示该步在价值意义下越存在改进空间，越值得在后续策略提炼过程中被重点关注；l_hat 接近零则表示该步动作已较为合理。该阶段不改变原始轨迹中的动作标签，仅对每一步附加一个「重要程度评分」，并写入 l_hat.csv，为后续加权抽样提供依据。l_hat 的分布形态（均值、极值、偏态程度）将决定 weights 是高度集中于少数关键步，还是相对均匀地覆盖全表，从而间接影响最终规则更偏向「关键态势」还是「全表平均行为」。

## 采样权重生成（weights）

基于逐步价值差距结果，系统将 l_hat 转换为可用于 VIPER 抽样的概率权重。系统对每一行样本取非负部分并加入平滑项，经归一化后得到 weights，使 l_hat 较大的样本在后续训练中获得更高的被抽样概率，而普通样本仍保留极小但非零的参与机会，从而避免训练过程完全忽略低价值差距区域。需要强调的是，该步骤仅改变「哪些样本被更频繁地学习」，并不改变样本本身的动作标签，因此决策树仍然学习的是轨迹中真实发生的行为，而非 Q 网络直接推荐的最优动作。权重分布的集中程度由 weights_eps 等参数调节：权重越集中，规则越偏向 Q 所标注的关键态势；权重越均匀，规则越接近对全表行为的平均模仿。本步输出 weights.csv，供 VIPER 多轮训练共用，且在本轮流水线内不再重复计算。

## VIPER 加权抽样与 CART 决策树训练

在获得采样权重后，系统进入 VIPER 与 CART 联合训练阶段，这是整条流水线中决策规则真正生成的核心环节。系统以八维状态为输入特征、以轨迹中实际动作为输出标签，按照 weights 所定义的概率分布进行多轮有放回重采样；每一轮训练一棵 CART 决策树，并在全量数据上评估其预测准确率（acc_full）与在重采样集上的准确率（acc_resampled）。通过多轮抽样与训练，系统在不同随机子样本上获得多棵候选树，并默认选取在全量轨迹上表现最优的一轮作为最终模型。由于训练标签始终来自原始轨迹而非 Q 网络输出，因此该阶段本质上是对行为数据的加权模仿学习，只是学习重点由 Q 网络所标注的关键时刻引导。树的深度、叶节点最小样本数、VIPER 轮数等参数控制规则复杂度与过拟合程度：树越深、叶约束越小，规则条数通常越多，全量准确率可能上升，但 acc_resampled 与 acc_full 之间的差距也可能扩大，可解释性与稳定性相应下降。本步在 viper_out 目录下记录各轮准确率及最终选用的决策树模型，为规则提取提供结构基础。

## 网格调参与最优结构选择（可选）

当启用 run_viper_tune_grid 时，系统在固定 FQE 与 weights 的前提下，对多组决策树超参数（如最大深度与叶节点最小样本数）进行网格搜索，分别完成 VIPER 训练并比较各组在全量数据上的准确率与规则规模，最终将表现最优的一组参数所对应的决策树导出为正式结果。该步骤不重新训练 Q 网络，也不重新计算权重，仅在同一价值评估与抽样框架下寻找更适合当前数据规模的树结构配置。对于大样本数据，网格搜索有助于在准确率与规则可读性之间取得平衡；对于小样本数据，应使用较浅的树与较大的叶节点约束，以避免过拟合。网格对比结果写入 viper_tune 目录（如 tune_results.csv、best_run_config.json），最优配置可回写 run_pipeline.py 的 RUN_CONFIG，用于后续正式交付运行。若未启用网格，则直接使用 RUN_CONFIG 中指定的 cart_max_depth、cart_min_samples_leaf 等单组参数完成训练。

## 规则提取与决策树可视化导出

在最终决策树确定后，系统对树结构进行深度优先遍历，将从根节点到各叶节点的分裂条件串联为 IF-THEN 形式的决策规则，并将动作编号映射为业务可读的机动名称（如「爬升1」「斜切切线机动」等），输出至 rules.txt 与 rules.json。同时，系统导出嵌套树结构（tree.json）、节点明细表（tree_nodes.csv）以及 Graphviz 流程图（policy_tree.pdf），便于业务人员阅读、评审与二次开发。部署使用时，系统或操作人员只需输入当前八维状态，按规则顺序匹配第一条满足条件的 IF 分支，即可得到推荐动作，无需再访问原始轨迹表或 Q 网络。因此，运行时智能体跟随的是规则手册，而非逐行查表；规则内容则来源于对加权行为数据的压缩与归纳，在 Q 所标注的关键态势上更贴近轨迹中的真实行为，在一般态势上则体现为对行为分布的粗粒度概括。

## 全流程汇总与衔接校验

流水线结束时，系统将各阶段配置、样本规模、FQE 损失、VIPER 准确率、规则条数及输出路径等信息写入 final_result.json，形成一次运行的完整档案。若开启 run_verify，系统自动校验 q_hat.pt、l_hat.csv、weights.csv 与 viper_out 之间的行数一致性与阶段衔接关系，确保各阶段产物可被独立复用或分阶段重跑。例如，在 Q 网络已训练完成的情况下，可仅重新计算权重并训练决策树，而无需重复 FQE，从而支持快速调参与对比实验。至此，系统完成从原始轨迹数据到可解释决策规则的完整转化：Q 网络负责识别关键决策时刻，VIPER 与 CART 负责在关键时刻上重点提炼行为规律，规则导出负责将结果转化为面向业务与部署的可读策略手册。
