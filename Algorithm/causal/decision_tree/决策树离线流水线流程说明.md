# 决策树离线流水线流程说明 

## 概述 

本系统实现从离线轨迹数据到可解释决策规则的完整转化，核心流程为「FQE 价值评估 → l_hat 重要性评分 → VIPER 加权抽样 → CART 规则提炼 → 规则集成」。系统支持两种运行模式：
- **rules 模式**（默认）：全表参与建树，专注规则展示与策略归纳
- **eval 模式**：按 episode 划分训练/验证/测试集，用于泛化指标评估

---

## 阶段 1：轨迹数据接入与预处理 

### 1.1 数据输入 

系统接收由仿真或专家飞行导出的离线轨迹数据（CSV 格式），每一行对应一次控制决策时刻，必需字段包括：
- **状态特征**：当前八维状态（s_0 至 s_7）、下一时刻状态（s_next_0 至 s_next_7）
- **动作与奖励**：实际执行动作（action）、即时奖励（reward）
- **回合信息**：回合编号（episode）、终止标志（dw）、截断标志（truncated）

### 1.2 数据清洗与预处理 

系统执行以下预处理步骤：
1. **完整性校验**：确保状态、动作、奖励无缺失或非法值
2. **奖励归一化**（可选）：对奖励值进行裁剪和标准化处理，支持按回合分别归一化以保留相对奖励结构
3. **转移构造**：生成状态转移样本，供后续 FQE 训练使用

### 1.3 关键影响 

本阶段不生成策略规则，但直接决定后续全链路分析的样本规模、动作分布与数据质量上限。若输入数据存在缺失、噪声或样本量不足，将限制后续 Q 估计与决策树泛化能力。

### 1.4 输出产物 

预处理后的轨迹表与转移样本进入内存，为后续阶段提供训练样本和标签来源。

---

## 阶段 2：FQE 价值网络训练（Q_hat） 

### 2.1 核心功能 

利用神经网络对「在给定状态下执行某一动作的长期价值」进行离线估计，得到价值函数近似 Q_hat(s, a)。

### 2.2 训练机制 

训练采用三层全连接神经网络，通过 Bellman 自举方式学习：
- **SARSA 模式**（默认）：使用轨迹中真实的下一步动作计算目标值，贴近行为策略
- **Max-Q 模式**：使用所有可能动作中的最大 Q 值计算目标值，更乐观

训练过程采用 Adam 优化器和余弦退火学习率调度，可选启用目标网络稳定训练过程。

### 2.3 关键影响 

Q 网络不直接参与在线决策，而是作为后续步骤的「价值评估器」。FQE 训练是否稳定、损失是否收敛，直接影响后续 l_hat 与权重计算的可信度，进而影响 VIPER 抽样重点是否合理。

### 2.4 输出产物 

- `q_hat.pt`：Q 网络权重与元信息
- 训练损失曲线：用于判断收敛性

---

## 阶段 3：逐步价值差距计算（l_hat） 

### 3.1 计算逻辑 

冻结 Q 网络参数后，对轨迹中每一行样本逐行评估：
- V_hat：当前状态下所有候选动作的最大 Q 值
- Q_sa：实际执行动作对应的 Q 值
- l_hat = V_hat - Q_sa：价值差距，越大表示改进空间越大
- a_star：Q 网络推荐的最优动作

### 3.2 输出产物 

`l_hat.csv`：包含价值差距、最优动作等字段，行数与原始轨迹 CSV 完全一致。

### 3.3 关键影响 

l_hat 的分布形态决定权重的集中程度：高度集中于少数关键步骤，或相对均匀地覆盖全表，间接影响最终规则偏向「关键态势」还是「全表平均行为」。

---

## 阶段 4：采样权重生成（weights） 

### 4.1 权重计算 

基于 l_hat 结果转换为 VIPER 抽样概率权重：
- 对每行样本取非负部分并加入平滑项
- 归一化处理使权重之和为 1
- 支持多种权重模式：margin（按 top1-top2 差距加权）、advantage（按 l_hat 直接加权）、uniform（均匀权重）

### 4.2 关键特性 

该步骤仅改变「哪些样本被更频繁地学习」，不改变样本本身的动作标签。权重分布的集中程度由平滑项参数调节，确保普通样本仍保留极小但非零的参与机会。

### 4.3 输出产物 

`weights.csv`：每样本的抽样权重，供 VIPER 多轮训练共用。

---

## 阶段 5：VIPER 加权抽样与 CART 决策树训练 

### 5.1 核心流程 

这是规则生成的核心环节，执行多轮循环：
1. 按权重有放回重采样得到训练子集
2. 在子集上训练 CART 决策树
3. 在评估集上计算准确率等指标
4. 选择在评估集上表现最优的一轮作为最终模型

### 5.2 Oracle 重标注（可选） 

启用时将训练标签从实际动作替换为 Q 网络推荐的最优动作，消除探索噪声对标签的影响，提升规则质量。

### 5.3 输出产物 

- `viper_summary.json`：各轮准确率、选轮结果
- `metrics.json`：训练/验证/测试集评估指标（eval 模式）

---

## 阶段 6：规则集成（可选） 

### 6.1 核心思想 

从多轮 VIPER 规则中提取稳定、高置信度的规则：
1. 收集所有轮次的规则
2. 按特征模式去重，相同特征和操作符的规则合并
3. 取中位数阈值作为最终阈值
4. 按置信度和支持度排序，选取前 N 条规则

### 6.2 输出产物 

- `ensemble_rules.txt`：集成后的 IF-THEN 规则
- `ensemble_rules.json`：规则详细信息（置信度、支持轮数等）

---

## 阶段 7：规则提取与决策树可视化导出 

### 7.1 规则提取 

对最终决策树进行深度优先遍历，生成 IF-THEN 形式的决策规则，并将动作编号映射为业务可读的机动名称。

### 7.2 可视化输出 

- `rules.txt`：人类可读的规则列表
- `rules.json`：规则的 JSON 结构化表示
- `tree.json`：嵌套树结构（便于程序读取）
- `tree_nodes.csv`：节点明细表（含类别分布、基尼系数）
- `policy_tree.pdf`：Graphviz 流程图
- `policy_tree.png`：PNG 格式树图（可选）

### 7.3 部署使用 

运行时只需输入当前八维状态，按规则顺序匹配第一条满足条件的分支，即可得到推荐动作，无需访问原始轨迹或 Q 网络。

---

## 阶段 8：全流程汇总与衔接校验 

### 8.1 汇总报告 

系统将各阶段配置、样本规模、FQE 损失、VIPER 准确率、规则条数及输出路径等信息写入 `final_result.json`，形成完整的运行档案。

### 8.2 数据流转追踪 

通过 `data_flow_report.json` 记录各阶段数据变化，包括奖励归一化裁剪数量、数据集划分规模、重采样样本数、规则集成前后规则数变化等。

### 8.3 分阶段重跑支持 

各阶段产物可独立复用，支持快速调参与对比实验。例如，已训练的 Q 网络可跳过 FQE 阶段，直接计算 l_hat。

## 典型场景与参数建议 

### 场景 1：大样本数据（>10 万行） 
- 目标：在准确率与规则可读性间取得平衡
- 建议：增加训练轮数，使用较大的网络隐层宽度，启用规则集成

### 场景 2：小样本数据（<1 万行） 
- 目标：避免过拟合，保证规则稳定性
- 建议：减少训练轮数，使用较小的网络宽度，限制树深度，降低集成要求

### 场景 3：类别不均衡数据 
- 目标：避免多数类主导规则
- 建议：使用类别加权，选择宏平均 F1 作为选轮指标，考虑启用 Oracle 重标注

---

## 常见问题与解决方案 

### Q1：FQE loss 震荡不收敛 
- **原因**：学习率过高、批次大小过小、奖励值范围过大
- **解决方案**：降低学习率、增大批次大小、启用奖励归一化、启用目标网络

### Q2：VIPER 选轮指标虚高 
- **原因**：小样本下 Q 网络塌缩为常数策略
- **解决方案**：增大轨迹数据量、关闭 Oracle 重标注、减小网络隐层宽度

### Q3：规则数量过多/过少 
- **规则过多**：减小树深度、增大叶节点最小样本数、启用代价复杂度剪枝
- **规则过少**：增大树深度、减小叶节点最小样本数、减小剪枝系数

### Q4：规则泛化能力差 
- **原因**：树过深、样本量不足、类别不均衡
- **解决方案**：使用较浅的树、启用规则集成、使用类别加权

## 运行方式 

修改 `run_pipeline.py` 中的配置（至少填写轨迹 CSV 路径），然后执行：
```bash
python causal/decision_tree/run_pipeline.py
```
