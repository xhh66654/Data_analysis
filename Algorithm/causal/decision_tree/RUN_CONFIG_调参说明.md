# run_pipeline.py — `RUN_CONFIG` 调参说明（作用版）

流水线在干什么（先有个底）：

1. **FQE**：用神经网络学一个「状态 + 动作 → 长期价值」的近似 \(Q(s,a)\)，存成 `q_hat.pt`。  
2. **l_hat**：对每个时刻算「当时动作比 Q 认为最好的动作差多少」→ 越大越像「该纠错的步」。  
3. **weights**：把 l_hat 变成抽样概率（重要步被多抽到）。  
4. **VIPER + CART**：按权重反复抽样、训练决策树，导出 **IF-THEN 规则** 和树图。

下面每个参数都写四块：**作用**、**在程序里管什么**、**一般怎么调**、**调狠了会怎样**。

---

## 路径

### `trajectory_csv`

- **作用**：你要分析的那一份飞行/控制轨迹表，每一行是一次「在某状态下选了什么动作、得了什么奖励」等。  
- **在程序里管什么**：决定有多少条样本、动作四类各占多少、状态分布长什么样；后面所有结果都建在这张表上。  
- **一般怎么调**：换数据就改路径；列名要符合 `run_pipeline` 文档要求。  
- **换表会怎样**：N 变大变小、acc 上限、规则形状都会变，和旧结果不能直接比「谁更好」除非控制同一份表。

### `output_dir`

- **作用**：所有输出（`q_hat.pt`、`l_hat.csv`、`weights.csv`、`viper_out/`）往哪里写。  
- **在程序里管什么**：空字符串 `""` 时，自动写到「轨迹 CSV 所在文件夹」下的 `fqe_out/`。  
- **一般怎么调**：想集中存盘就写绝对路径；否则留空最省事。  
- **改它会怎样**：只改保存位置，**不改算法结果**。

## 阶段 1：FQE（训练 Q 网络）

### `fqe_epochs`

- **作用**：神经网络把整份转移数据「完整扫几遍」算几轮训练（epoch）。  
- **在程序里管什么**：迭代更新 `q_hat` 的次数越多，理论上更能拟合，但也可能越过最优点或过拟合。  
- **一般怎么调**：小数据约 15～40；上百万行常用 15～30；(loss 不降反弹就别盲加 epoch)。  
- **调狠了会怎样**：太少 → Q 不准；太多 → loss 抖动、过拟合，后面 l_hat / 权重跟着歪。
- **目前调整**：1万条数据采用50轮效果与时间的性价比高，100万条数据采用15轮比较好

### `fqe_device`

- **作用**：用显卡还是只用 CPU 算神经网络。  
- **在程序里管什么**：只影响矩阵运算在哪跑。  
- **一般怎么调**：有 NVIDIA 显卡且装好 PyTorch CUDA 就用 `"cuda"`；没有就用 `"cpu"`。  
- **改它会会怎样**：同一随机种子数值应一致（除非法术级数值差）；**只差速度**。
- **目前调整**：使用cuda

### `fqe_target`

- **作用**：训练时「下一状态的 Q」怎么取值：是跟轨迹里**真实走的下一步动作**一致（贴近你数据里的行为），还是用 **Q 自己认为下一阶段最好的动作**（更乐观）。  
- **在程序里管什么**：`sarsa`：目标里用轨迹的 \(a'\)。`max_q`：目标里用 \(\max_{a'} Q(s',a')\)。  
- **一般怎么调**：想和行为策略对齐、解释「专家怎么走」→ 常用 **`sarsa`**。想突出「哪些地方动作明显不够好」→ 可试 **`max_q`**（l_hat、权重会变猛）。  
- **改它会怎样**：改这一项，\(Q\) 含义都变了；**和以前实验不能直接比数值**。
- **目前调整**：采用sarsa

### `fqe_gamma`“这个很重要”

- **作用**：未来的奖励要打几折到今天看；越接近 1，越看重「很远以后」的收益。  
- **在程序里管什么**：出现在贝尔曼目标：`r + γ × (没到终点时的下一步价值)`。  
- **一般怎么调**：长回合任务常见 **0.99**；若回报主要在近期，可试 **0.95～0.99**。  
- **改它会怎样**：改 γ，Q 的尺度与相对大小都会变；**整条链与旧实验不可比**。
- **目前调整**：数据量比较少的时候采用0.95，测试数据量1万，数据量大时采用0.99，测试数据为100万

### `fqe_lr`

- **作用**：神经网络每一步沿梯度走多远（学习率）。  
- **在程序里管什么**：Adam 的步长；太大容易震荡或发散，太小学不动。  
- **一般怎么调**：常见 **1e-4～5e-3**；**不建议 5e-2 这种特别大**（小数据更容易炸）。  
- **调狠了会怎样**：过大 → loss 乱跳、Q 不可用；过小 → loss 居高不下、学得慢。
- **目前调整**：选择5e-2效果是最好的，5e-1与5e-4的效果都不好，特别是5e-1效果极差，

### `fqe_batch_size`

- **作用**：每次更新权重时用多少条转移拼成一批来算梯度。  
- **在程序里管什么**：一批越大，单次梯度越「平均」，但显存占用高；样本总数 N 很小时，一批若接近 N，每个 epoch 里更新步数就很少。  
- **一般怎么调**：256～1024（看显存）；**几千行数据可先试 256～512**。  
- **改它会怎样**：主要影响**收敛稳定性和速度**；设得离谱时等效改变了有效学习率尺度。
- **目前调整**：1024比较好

### `fqe_hidden`

- **作用**：神经网络中间层有多少个神经元（容量多大）。  
- **在程序里管什么**：网越宽越能捏复杂函数，也越需要数据和正则。  
- **一般怎么调**：常用 **128～256**；**数据很少时用 128 或更小**更合适。  
- **调狠了会怎样**：过大 + 样本少 → 过拟合，Q 在训练集上好、泛化差，后面树也会怪。
- **目前调整**：128VIPER 全量准确率更最高：`acc_full = 0.6117`，VIPER 重采样：第二组 acc_resampled = 0.8777

  ​		    512VIPER 全量准确率其次：`acc_full = 0.6108`，VIPER 重采样：第二组 acc_resampled = 0.8368

### `fqe_use_target_network`

- **作用**：是否用一套「慢一点更新的目标 Q」来算训练目标（像 DQN 里那种 target net），减小目标一直在动带来的抖动。  
- **在程序里管什么**：为 True 时 TD 目标更稳，但每步计算略多。  
- **一般怎么调**：大表或 loss 曲线乱 → **开 True**；极小表可关，差别未必大。  
- **改它会怎样**：主要影响 **loss 是否平稳、能否训稳**。
- **目前调整**：True

## 阶段 2：l_hat

### `l_hat_batch_size`

- **作用**：算 l_hat 时，一次塞进 GPU 多少行做前向推理（只是把大块拆小，不是训练 batch）。  
- **在程序里管什么**：只影响显存峰值和耗时。  
- **一般怎么调**：256～4096，爆显存就调小。  
- **改它会怎样**：**理论上与 l_hat 数值无关**（同一模型下）。
- **目前调整**：影响不大

## 阶段 3：weights

### `viper_weighted_sampling`

- **作用**：决定 VIPER 每轮 bootstrap 是按 **l_hat 加权** 抽样，还是 **均匀** 抽样（每条样本概率相同）。  
- **在程序里管什么**：`True` → 用 `max(l_hat,0)+eps` 再归一化得到 `weights`；`False` → 直接 `weights=1/n`，**此时 `weights_eps` 不生效**。  
- **一般怎么调**：主 KPI 是 **acc_full（全表准确率）** → 优先 **`False`**（S0_4 上约 **69%** 且 20 轮稳定）；想 **轻微盯住高 l_hat 步** → **`True`** 并配合较大的 `weights_eps`（见下）。  
- **调狠了会怎样**：`True` 且 `weights_eps` 过小 → `acc_resampled` 可很高（如 ~77%）但 `acc_full` 易掉到 ~49%～67% 且波动大；`False` → 接近均匀 CART，`acc_resampled ≈ acc_full`。  
- **目前调整**：S0_4 上 **`False` 全量更稳更高**（acc_full≈69.5%）；小数据也建议优先均匀。

### `weights_eps`

- **作用**：在加权模式下，给每个样本的 `w_raw` 加一个 **相对 l_hat 尺度的「底」**；拉大高低 l_hat 样本之间的相对差距，或让抽样更接近均匀。  
- **在程序里管什么**：仅当 **`viper_weighted_sampling=True`** 时生效：先 `w_raw_i = max(l_hat_i, 0) + eps`，再归一化为 `weights_i`（供 `np.random.choice(..., p=weights)`）。**不能设为 0**（程序要求 `eps>0`）。  
- **一般怎么调**：**关键看 `eps` 与典型 `l_hat` 的比值**，不是绝对大小 alone：  
  - **远小于典型 l_hat**（如 **1e-6～1e-4**，且 mean(l_hat)≈1）→ **强 VIPER**，难样本相对多抽很多倍；  
  - **与典型 l_hat 同量级**（如 **0.5～2.0**，mean(l_hat)≈1～1.5）→ **轻微倾斜**（「适当高一点点难样本」）；  
  - **远大于典型 l_hat**（如 **5～10**）→ 接近均匀，VIPER 重点纠错变淡。  
  例：l_hat=0 / 1.45 / 10 三档，eps=1e-3 时最难约是最易的 **~10000 倍**；eps=1.0 时约 **~11 倍**；eps=5.0 时约 **~3 倍**。  
- **调狠了会怎样**：过小（相对 l_hat）→ 几乎总抽高 l_hat「尖子」样本，树偏激、`acc_full` 差；过大 → 加权意义变淡，接近 `viper_weighted_sampling=False`。  
- **目前调整**：**全表 acc 优先时不依赖此项**（用 `viper_weighted_sampling=False`）；若开加权且要轻微倾斜，S0_4 可先试 **eps=1.0**（再试 0.5～2.0），勿用小数据上 **1e-4 档**（仍是强 VIPER）。

## 阶段 4～6：VIPER + CART

### `run_viper_tune_grid`

- **作用**：要不要自动试很多组「树的深度 × 叶子最少样本」，选全量准确率最好的一组再把规则写到 `viper_out`。  
- **在程序里管什么**：`True` → 跑 `tune_viper.py` 里的 **`TUNE_GRID`**，结果在 `fqe_out/viper_tune/`。`False` → 只用下面的 `cart_*` 一组参数训一次。  
- **一般怎么调**：定型、省时间 → **False**；系统找参数 → **True**（时间会乘网格组数）。  
- **改它会怎样**：不关算法公式，只决定**是否多跑若干组 depth/leaf 并替你选优胜**。
- **目前调整**：

### `viper_n_round`

- **作用**：VIPER 外圈循环跑多少轮：**每一轮都按权重随机抽一批行，训一棵小树，再在全体数据上看准确率**。  
- **在程序里管什么**：轮数越多，随机抽样组合越多，有可能某一轮碰巧更好。  
- **一般怎么调**：常用 **8**；数据少可以试试 **5** 减轻过拟合挑轮次。  
- **调狠了会怎样**：过少 → 可能没抽到好树；过多 → **计算量增加**，还可能「挑到过拟合那一轮」。

### `viper_pick_best_round`

- **作用**：最后是保留「全集准确率最高的那一轮」的树，还是「不管好坏就用最后一轮」。  
- **在程序里管什么**：映射到 sklearn 里是选 best model 还是用最后一棵。  
- **一般怎么调**：想要稳定、可看全量表现 → **`True`**；做消融或强制看最后一轮 → `False`。  
- **改它会怎样**：`True` → 输出树往往 **全量准确率更好**；`False` → 更简单但可能更差。

### `cart_max_depth`

- **作用**：限制决策树 **从根到叶最多经过几次 IF 分裂**（不是「总共几条规则」）。例如 **7** 表示单条规则里 **最多约 7 个 AND 条件**。  
- **在程序里管什么**：sklearn `max_depth`；**一条 IF-THEN 规则 = 一片叶子**，树越深 → 切得越细 → **叶子/规则通常越多**、越贴数据细节。受 `cart_min_samples_leaf` 等约束时，**实际深度可能小于该上限**。  
- **一般怎么调**：小样本 **4～7**；S0_4 量级（47 万行）均匀抽样：**5 → acc_full≈69%、规则~32 条；7 → ≈71%、规则~100+ 条**；可跑 `tune_viper.py` 再填回。  
- **调狠了会怎样**：太深 → 规则暴增、难读、易过拟合，acc 收益递减；太浅 → 规则少、acc_full 偏低。  
- **目前调整**：acc_full 优先时 S0_4 建议 **7**；要规则少、可读 → **5**。

### `cart_min_samples_leaf`

- **作用**：一片叶子里 **至少有多少条样本** 才允许停在这里；与 `cart_max_depth` 一起决定树能长多细。  
- **在程序里管什么**：sklearn `min_samples_leaf`；样本不够分时 **提前停分裂**，实际层数可 **低于** `cart_max_depth`。  
- **一般怎么调**：要 **少规则、更稳** → **50～200**（视 N）；想极致贴合 → 1（易过拟合）。  
- **调狠了会怎样**：偏大 → 规则变少、树变「呆」、acc_full 常略降；偏小 → 规则暴增、像在记噪声。  
- **目前调整**：S0_4 常用 **50**，与 depth=7 搭配。

### `cart_min_samples_split`

- **作用**：一个结点要想再分裂成左右两个儿子，结点里至少要累计有多少条样本。  
- **在程序里管什么**：sklearn `min_samples_split`（代码里为 2 时等价于默认值）。  
- **一般怎么调**：默认可先 **2**；想更强剪枝可与 `min_samples_leaf` 配合，例如 **≥ 2×leaf**。  
- **调狠了会怎样**：偏大 → **树更矮、更少分裂**，更稳更少规则；偏小 → 更细碎的树。

### `resample_size`

- **作用**：VIPER **每一轮**不是用全部 N 行来训练决策树内部的抽样，而是从 N 里有放回抽 **M** 行（像 bootstrap）。**填 0 表示 M=N**，即还是用全部样本量去抽一轮（仍是带权有放回）。  
- **在程序里管什么**：控制每棵树见过的「有效行数」规模。  
- **一般怎么调**：标准写法 **0**；想刻意让每棵树看更少数据可设 \(M<N\)（实验用）。  
- **调狠了会怎样**：M 远小于 N → 树更片面、方差更大，有时为了减少算力或对极大 N 抽样。

### `weight_noise`

- **作用**：每一轮 VIPER 开始前，对 `weights` 做 **乘性随机扰动** 再归一化，让各轮 bootstrap 抽到的样本组合不完全相同。  
- **在程序里管什么**：`w' = w × (1 + N(0, weight_noise))` 后重新归一化；**0 表示不扰动**，每轮抽样概率完全相同（只靠 CART 的 `random_state+轮次` 产生差异）。  
- **一般怎么调**：  
  - **0**：最稳、可复现；**均匀抽样**且 `acc_full` 已稳定时优先（如 S0_4 均匀 ~69.5%）；  
  - **0.01**：**轻**扰动，约 ±1% 量级改变各样本相对权重，略增轮间多样性；  
  - **0.02**：**中**扰动，约 ±2% 量级，加权 VIPER、多轮选优时较常用；  
  - **>0.05**：扰动偏大，抽样分布易偏离原 `weights`，不推荐。  
- **调狠了会怎样**：0 → 多轮多样性弱但方差小；过大 → 每轮抽样几乎随机，VIPER「谁重要」失效，易出现差轮。  
- **目前调整**：均匀模式 **`0` 更好**；开加权且 `viper_n_round` 较多时可试 **0.01～0.02**。

## 导出树与图（不影响训练数值）

### `export_tree`

- **作用**：除 `rules.txt` 外，要不要导出机器可读的结构：`tree.json`、结点表、`dot` 等。  
- **在程序里管什么**：关则少写文件；开则方便前后端或其它工具读树。  
- **一般怎么调**：需要对接系统 → **True**；只要人类可读规则 → 可 False。  
- **改它会怎样**：**不改训练到的树**，只决定写哪些副产品。

### `render_tree_pdf`

- **作用**：要不要用 Graphviz 把决策树画成 **PDF**。  
- **在程序里管什么**：依赖本机装好 Graphviz 且 Python 装好 `graphviz` 包。  
- **一般怎么调**：要看图 → True； CI 或无 Graphviz → False。  
- **改它会怎样**：只影响是否生成 **`policy_tree.pdf`**。

### `render_tree_png`

- **作用**：要不要再导出一张 **PNG** 树图（或某些失败路径下用 matplotlib 兜底）。  
- **在程序里管什么**：多一种图片格式；可能文件较大。  
- **一般怎么调**：需要帖 PPT/web → True。  
- **改它会会怎样**：不改树，只多/少 PNG。

### `tree_image_dpi`

- **作用**：在用 matplotlib **回退画 PNG** 时，分辨率（每英寸点数）。  
- **在程序里管什么**：仅影响 PNG 清晰度和体积。  
- **一般怎么调**：100～200。  
- **改它会怎样**：只影响图文件观感。

### `open_tree_pdf` / `show_tree_image`

- **作用**：图做好后要不要用系统默认程序**自动弹出**看图。  
- **在程序里管什么**：本机桌面行为；服务器上常关。  
- **一般怎么调**：本地调试可 True；批处理管线 False。

## 全局

### `seed`

- **作用**：随机数发生器起点；让所有「随机」部分可重现。  
- **在程序里管什么**：FQE 初始化/抽样顺序、VIPER 抽样、决策树里的 `random_state+轮次` 等。  
- **一般怎么调**：任意固定整数即可；对比实验要保持一致。  
- **改它会怎样**：**树结构、准确率数字会变**（同一配置下仍可比较趋势）。

### `run_verify`

- **作用**：跑完后要不要自动跑一遍 `verify_e2e`，检查各阶段文件衔接是否一致。  
- **一般怎么调**：开发/正式跑 pipeline → **True**；你确信中间被人手改过文件、`False` 可跳过（不推荐长期关）。  
- **改它会怎样**：失败会直接报错退出；不改变训练逻辑。

### `verbose`

- **作用**：控制台是否打出大量 INFO 日志（FQE epoch、VIPER 每轮准确率等）。  
- **一般怎么调**：想看进度 True；要少刷屏 False。  
- **改它会怎样**：**不改任何数值结果**。
