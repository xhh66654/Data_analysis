# 决策树训练流程

若动作为 **10 维联合模式、每步 1～3 维变化**，在进 CSV 前需先完成动作编码（战术库 + 轨迹模式合并），仍使用单列 `action`；见 [十维动作-轨迹模式与战术库决策方案.md](./十维动作-轨迹模式与战术库决策方案.md)。

---

## 轨迹数据接入与预处理

系统首先接收由仿真或专家飞行导出的离线轨迹数据，数据以 CSV 形式存储，未来修改成根据数据表拼接的结构，每一行对应一次控制决策时刻。数据包含当前八维状态特征（s_0 至 s_7）、下一时刻状态（s_next_0 至 s_next_7，修改成从下一条决策决策空间获取）、实际执行动作（action）、即时奖励（reward，如果构建成10课树，需要将每一个维度的奖励值都表示出来）、回合编号（episode）以及终止标志（dw、truncated）等字段。模块通过 `trajectory_io.load_trajectory_csv` 读入全表，校验必需列是否存在，并对状态、动作与奖励做数值检查，排除 NaN 与非法动作编号；随后按「同 episode 内相邻步」规则构造状态转移（当前 s、动作 a、奖励 r、下一状态 s'、done 标志及 SARSA 所需的下一步动作 a'），形成供 FQE 使用的 `TransitionBatch`，**行数与 CSV 一致，不在此阶段删行**。

在默认配置下，系统还可选启用**奖励归一化**（`enable_reward_norm`）：对 reward 做裁剪与标准化，仅改变奖励数值，不改变样本条数，用于提升 FQE 训练稳定性。该阶段不生成策略规则，但直接决定后续全链路分析的样本规模、动作类别数（`n_actions`）与数据质量上限；若输入数据存在缺失、噪声或有效动作类过多且样本极稀疏，将限制后续 Q 估计与决策树的可解释性。本步完成后，轨迹表与转移构造结果进入内存，并写入数据流转追踪（`data_flow` 阶段 00～01），为 FQE 提供训练样本；在 `oracle_relabel=False` 时，决策树阶段的标签直接来自 CSV 中的 `action`，在 `oracle_relabel=True` 时，标签将在 VIPER 阶段改为 Q 意义下的最优动作（见后文）。

注释：

1）状态、动作、奖励无缺失或非法值

2）奖励值进行裁剪和标准化处理，支持按回合分别归一化以保留相对奖励结构，目前奖励值的范围是通过"reward_clip_min"与

  "reward_clip_max"控制的，大于或小于这个值，都会转成这2个值

  3）进行数据转移构造，构造成：(s₀, a₀, r₀, s₁, 0, a₁) — 从 s₀ 执行 a₀，获得奖励 r₀，到达 s₁，未终止，下一步动作是 a₁

## FQE 价值网络训练（Q_hat）

在数据预处理完成后，系统引入 FQE（Fitted Q Evaluation，拟合 Q 评估）方法，利用神经网络 `QHatNetwork` 对「在给定状态下执行某一离散动作的长期价值」进行离线估计，得到价值函数近似 Q_hat(s,a)，并保存为 **`fqe_out/q_hat.pt`**（含 `state_dim`、`n_actions`、训练超参与 loss 历史等元数据）。训练过程中，系统以轨迹中的状态、动作、奖励及下一状态、下一动作（SARSA）或 max-Q 目标为监督信号，通过 Bellman 自举与 Adam 优化不断更新网络参数；可选启用目标网络（`fqe_use_target_network`）以稳定 TD 目标。网络结构为「8 维状态 → 隐层 → 隐层 → n_actions 维输出」，**对每一个时间步的前向传播会给出当前动作空间内全部候选动作的 Q 值向量**，训练损失则主要作用于该步轨迹中实际执行的动作所对应的 Q 分量。

该网络本身不直接参与在线决策，也不生成新的飞行轨迹，而是作为后续步骤的「价值评估器」，用于衡量每一步实际动作与价值意义下较优动作之间的差距，并为 VIPER 的 margin 加权提供基础。FQE 训练是否稳定、loss 是否收敛，将直接影响后续 l_hat 与 weights 的可信度，进而影响 VIPER 抽样重点是否合理；`n_actions` 越大（例如十维联合模式经战术库合并后的有效动作数），最后一层输出越宽，训练与 l_hat 推理的算力与存储需求也相应上升。本步输出 `q_hat.pt`，不直接产生 IF-THEN 规则，但为整条链路的加权模仿与可选 oracle 重标注提供价值标尺；数据流转记录为阶段 02，样本行数仍等于 CSV 全量。

注释：

1）训练机制：训练采用三层全连接神经网络，通过 Bellman 自举方式学习：

- **SARSA 模式**（默认）：使用轨迹中真实的下一步动作计算目标值，贴近行为策略
- **Max-Q 模式**：使用所有可能动作中的最大 Q 值计算目标值，更乐观

2）训练组件的介绍：

- **Adam 优化器**：是一种自适应学习率优化算法，用于更新神经网络的权重参数，像物理中的惯性一样，积累之前的梯度方向，加速收敛;RMSProp ：自适应调整每个参数的学习率。例如：蒙眼下山不仅看当前坡度，还记住之前走的方向（动量），并且根据之前的步伐大小调整步长（自适应学习率）
- **余弦退火学习率调度**：是一种学习率调整策略，让学习率在训练过程中周期性地变化，从初始学习率开始逐渐降低到最小值然后重新升高（可选，称为重启）重复这个过程。前期 ：大学习率可以快速探索参数空间；后期 ：小学习率可以精细调整参数；周期性重启 ：帮助跳出局部最优解
- **目标网络**：目标网络是一个独立于主网络的副本，用于稳定强化学习中的 Bellman 方程计算。在强化学习中，Q 值的目标是 target = r + γ * max Q(s', a') 。如果直接使用当前网络计算目标值，会导致：训练不稳定 ：目标值和预测值都来自同一个不断变化的网络；正反馈循环 ：网络参数更新会影响目标值，目标值变化又影响参数更新。创建一个与主网络结构相同的目标网络，目标网络的参数不参与梯度更新定期（或缓慢）将主网络的参数复制到目标网络，最后计算目标值时使用目标网络

## 逐步价值差距计算（l_hat）

在 Q 网络训练完成并冻结参数后，系统对轨迹中**每一行**样本进行逐行评估，计算该时刻在价值意义下的改进空间，并写入 **`fqe_out/l_hat.csv`**。具体而言，系统对每个状态 s 一次前向得到所有候选动作的 Q 值向量 `q_all`，取其中最大值作为 V_hat，再读取该时刻**实际执行动作**对应的 Q_sa，定义 **l_hat = V_hat − Q_sa**；l_hat 越大，表示该步相对价值最优动作越存在改进空间。与此同时，系统计算 **a_star = argmax_a Q(s,a)**（供可选 oracle 重标注使用），以及 **margin = Q_top1 − Q_top2**（反映各候选动作之间的区分度，供 VIPER 的 margin 权重模式使用）。该阶段不改变原始 CSV 中的 `action` 列，仅附加 Q 相关列与评分列；行数与轨迹表严格一致。数据流转记为阶段 03。`l_hat` 的分布形态将间接影响后续权重是高度集中于少数关键步，还是相对均匀地覆盖全表，从而影响最终规则更偏向「关键态势」还是「全表平均行为」。

注释：

1）将当前状态下的所有动作的Q值都计算一遍，将最大的Q值与真实Q值进行对比，得出一个差值，差值越大说明了模型在这个决策场景下的动作效果越差。

---

## 采样权重生成（weights）

基于 l_hat 结果及（在 margin 模式下）决策间隔 margin，系统将每行样本转换为 VIPER 多轮训练共用的抽样概率，输出 **`fqe_out/weights.csv`**。系统支持 `weight_mode`：**uniform**（均匀 1/n）、**advantage**（按 l_hat 非负部分加权）、**margin**（按 top1−top2 非负部分加权，默认推荐）。对非负部分加平滑项 `weights_eps` 后归一化，使高 l_hat 或高 margin 的样本在后续有放回抽样中获得更高概率，低分样本仍保留非零权重，避免训练完全忽略一般区域。该步骤**仅改变「哪些行被更频繁地抽到」**，在 `oracle_relabel=False` 时不改变 CART 所学标签；在 `oracle_relabel=True` 时，VIPER 将改用 l_hat 中的 `a_star` 作为树标签，此时权重影响的是「对 Q 最优动作模式的模仿重点」。权重越集中，规则越偏向价值标注的关键态势；越均匀，越接近对全表（或全表 oracle 标签）的平均模仿。数据流转记为阶段 04；本轮流水线内 weights 只计算一次，VIPER 多轮共用同一文件。

注释：

1）将I_hat结果转化维VIPER抽样概率权重，对每行样本取非负部分并加入平滑项，归一化处理使权重之和为 1，支持多种权重模式：margin（按 top1-top2 差距加权）、advantage（按 l_hat 直接加权）、uniform（均匀权重）

2）此模块作用只有是哪些样本被更频繁学习，不修改样本本身的动作标签，权重分布的集中程度由平滑项参数调节，确保普通样本仍保留极小但非零的参与机会

3）样本权重供VIPER多轮训练使用

## 规则提炼模式与 VIPER 数据范围

在进入 VIPER 之前，系统根据 **`pipeline_mode`** 确定决策树训练所使用的行集合（数据流转阶段 05～06）。**默认 `pipeline_mode="rules"`（规则提炼模式）**：不按 episode 划分 train/val/test，**用于建树与导出规则的全部轨迹行均参与 VIPER**（在仅指定 `only_episode` 时，FQE/l_hat/weights 仍通常对全表计算，但 VIPER 与规则导出仅使用该 episode 的子集，以便展示「单局」策略形态）。**可选 `pipeline_mode="eval"`**：按 episode 划分训练/验证/测试集，用于考察泛化指标（`metrics.json` 中 test 集准确率等），适用于实验对比而非默认交付；此时 `val_frac`、`test_frac` 生效，且可与 `refit_final_tree_on_full_data` 配合在选轮后于全表重训导出树。

本模块的主用途是**将大量轨迹压缩为可读的 IF-THEN 规则与决策树图**，而非默认追求 holdout 测试集上的预测比赛；因此全表参与建树的 `rules` 模式与「规则展示」目标一致。若需了解样本行数在何环节减少，可查看运行后生成的 **`data_flow_report.json`** 及日志中的 `[DATA-CROP]` 摘要。

---

## VIPER 加权抽样与 CART 决策树训练

在获得采样权重后，系统进入 VIPER 与 CART 联合训练阶段，这是整条流水线中**决策规则结构真正生成**的核心环节。系统以八维状态为输入特征、以动作标签为输出（来自 CSV 的 `action`，或 `oracle_relabel=True` 时的 `a_star`），按 `weights` 定义的概率进行 **多轮有放回 bootstrap 抽样**；默认每轮抽样规模 `resample_size=0` 时，每轮抽取的样本条数等于训练池行数（有放回，故同一行可重复出现）。每一轮在抽样集上训练一棵 `DecisionTreeClassifier`（CART），并可在评估集上计算选轮指标（默认 `viper_selection_metric=macro_f1`）；**`rules` 模式下评估集即为当前建树用的全池**，用于在多个随机子样本之间选取表现最佳的一轮树。

训练时可启用 **`cart_class_weight=balanced`**，以缓解动作类不均衡对分裂的影响；**决策树图与节点表上的「类别分布」展示为真实标签的百分比**（基于 `decision_path` 统计），**仅叶节点显示 class（THEN 动作名）**，中间节点不显示 class，以便与 IF-THEN 规则语义对齐。树的 `cart_max_depth`、`cart_min_samples_leaf`、`cart_min_samples_split`、`viper_n_round`、`weight_noise` 等参数控制规则复杂度、稳定性与多轮多样性：树越深、叶约束越小，单轮规则条数通常越多；轮数越多，为后续规则集成提供更丰富的候选。本步在 **`viper_out/`** 下保存各轮指标、`viper_summary.json`、最终选用的树模型及中间 metrics，为规则提取与可视化提供结构基础。数据流转阶段 07 记录每轮 bootstrap 规模（不减少训练池行数，仅影响有放回重复次数）。

注释：

1）按权重有放回重采样得到训练子集，在子集上训练 CART 决策树，在评估集上计算准确率等指标，选择在评估集上表现最优的一轮作为最终模型

## 规则集成与提纯（可选，默认开启）

当 **`run_rule_ensemble=True`**（`RUN_CONFIG` 默认）时，系统在选定单轮树模型之外，收集 VIPER **每一轮** CART 所提取的 IF-THEN 规则，按条件模式与动作进行跨轮投票与置信度排序，并截断至 **`ensemble_max_rules`** 条（如 200），将集成结果**回写** `rules.txt` 与 `rules.json`，同时在 `viper_out/ensemble_rules/` 下保存集成明细。该步骤不重新训练 Q 网络、不重新计算 l_hat 与 weights，而是在同一棵树结构候选之外，从多轮随机抽样中获得更稳定、可精简的规则子集，适合「多轮浅树 + Top-K 规则」的交付策略。规则集成**裁剪的是规则条数，不是轨迹行数**；数据流转阶段 10 记录集成前后规则数量变化。若关闭规则集成，则最终规则直接来自选中的那一轮树。

---

## 规则提取与决策树可视化导出

在最终决策树（及可选规则集成）确定后，系统对树结构进行深度优先遍历，将根到叶的路径串联为 **IF … THEN …** 形式，并将动作编号映射为业务可读名称（依赖 `DT/dt_auto_pipeline` 中的 `CLASS_MAPPING` 或外部模式对照表），输出至 **`viper_out/rules.txt`** 与 **`rules.json`**。同时导出嵌套结构 **`tree.json`**、节点明细 **`tree_nodes.csv`**、Graphviz 源文件 **`policy_tree_debug.dot`** 及流程图 **`policy_tree.pdf`**（需安装 Python `graphviz` 与系统 Graphviz）；可选渲染 PNG。

部署或评审时，业务人员可依据规则顺序对当前八维状态进行条件匹配，得到推荐动作类别；规则内容来源于对（加权）行为或 oracle 标签的压缩归纳：在权重与 Q 共同标注的关键区域更贴近重点行为，在其余区域则体现为粗粒度分布。若动作经十维战术库编码，须配合 **`MODE_TABLE`** 将 THEN 中的模式名还原为 10 维向量含义。本步对应数据流转之后无进一步删行；`viper_summary.json` 中可含根节点真实标签分布等摘要字段。

## 全流程汇总与产物档案

流水线结束时，系统将配置摘要、样本规模、FQE 最终 loss、VIPER 选轮指标、规则条数、各阶段输出路径等写入 **`fqe_out/final_result.json`**，并生成 **`fqe_out/data_flow_report.json`**（各阶段样本行数、是否删行及中文说明）。控制台打印规则预览与数据裁剪摘要，便于快速核对「全表 49 万行 → VIPER 是否全量参与」等关键问题。

各阶段产物可独立复用：例如已有 `q_hat.pt` 时，可修改权重相关配置后仅从 l_hat/weights/VIPER 重跑；已有 `weights.csv` 时，可仅重跑 VIPER 阶段（需通过代码调用 `run_viper_from_files` 或调整流程入口）。典型交付物包括：

| 阶段 | 主要输出 |
|------|----------|
| FQE | `q_hat.pt` |
| l_hat | `l_hat.csv` |
| weights | `weights.csv` |
| VIPER / 规则 | `viper_out/rules.txt`、`policy_tree.pdf`、`tree.json` |
| 汇总 | `final_result.json`、`data_flow_report.json` |

至此，系统完成从原始轨迹数据到可解释决策规则的转化：**Q 网络识别关键决策时刻并量化动作价值；weights 引导 VIPER 重点学习；CART 将行为（或 oracle 动作）归纳为状态分区；规则与 PDF 将结果转化为面向业务与评审的策略手册**。单步自然语言解释与效果验证可由同仓库下的 **`causal/step_explain`** 模块在指定 `(episode, global_step)` 上补充，其 FQE 默认独立训练，与本文流水线可并行使用。
