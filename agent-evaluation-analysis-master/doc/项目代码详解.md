## 1. 项目架构总览

```
命令入口                 配置文件
  main.py  ──────────  config.yaml
     │
     ▼
  src/service.py  ───────────── 对外 Python API
     │
     ├──► src/module_a_rules/   规则抽取服务
     │       pipelines/collect/preprocess/viper/extract/merge/verify
     │
     └──► src/module_c_counterfactual/  反事实推理服务
               inference_record/data_loader/rollback/counterfactual
               policy_model/transition_model/reward_model/surrogate_bundle
               causal_effect/cf_dataset/explain_nl/llm_explain
```

**核心流程**：`main.py`（命令行入口）→ `service.py`（服务编排）→ 各模块执行具体算法 → 输出结果到 `output/` 目录。

## 2. 根目录文件

### `main.py` — 命令行入口

- **作用**：程序的唯一命令行入口，接收用户参数并分发到对应的服务。
- **支持模式**：
  - `explain_a`：规则抽取（服务 A）
  - `explain_c`：反事实推理（服务 C）
  - `train`、`explain_b`、`render`：预留模式，尚未实现
- **输入**：命令行参数（`--mode`, `--inference_task_id`, `--agent_id`, `--sim_id`, `--decision`, `--out` 等）
- **输出**：打印结果到控制台，可选写入 JSON 文件
- **依赖**：`src.service`（`rule_extraction_service`, `counterfactual_service`）

### `config.yaml` — 全局配置

- **作用**：YAML 格式的全局配置文件
- **依赖**：被 `src/utils/config.py` 读取

### `requirements.txt` — Python 依赖清单

- 核心依赖：`numpy`, `scikit-learn`, `matplotlib`
- 可选依赖：`graphviz`（PDF 决策树）、`torch`/`transformers`（LLM 润色）、`pymysql`（Doris 连接）

- **依赖**：`module_a_rules.pipeline`, `module_c_counterfactual.*`

## 4. 服务编排层

### `src/module_c_counterfactual/data_loader.py` — 数据加载

- **作用**：从本地 JSON 文件或 Doris 数据库加载推理数据，构建 `InferenceRecord` 对象。
- **核心函数**：
  - `load_inference_records(task_id)` — 加载指定任务下全部仿真局的推理记录
  - `load_inference_record(task_id, sim_id)` — 加载单条记录
  - `list_inference_task_ids()` — 列出所有可用任务 ID
- **输入**：`inference_task_id`（字符串）
- **输出**：`List[InferenceRecord]`
- **模式**：`MOCK_MODE=True` 走本地 JSON；`False` 走 Doris 数据库
- **依赖**：`inference_record.py`（数据结构定义）

### `src/module_c_counterfactual/inference_record.py` — 核心数据结构

- **作用**：定义系统所有核心数据类，是整个项目的数据模型层。
- **核心类**：
  - `AgentMeta` — 智能体元信息（id、名称、装备类型）
  - `ActionItem` — 动作项定义（名称 + 可选值 + 是否连续）
  - `AgentDecision` — 单步单智能体的决策内容
  - `StepDecision` — 单步所有智能体的决策汇总
  - `AgentObservation` — 单步单智能体的观测内容（嵌套字典）
  - `StepObservation` — 单步所有智能体的观测汇总
  - `InferenceRecord` — **一次完整仿真的推理数据（主容器）**
- **关键方法**：
  - `InferenceRecord.get_obs_vector(t, agent_id)` — 获取展平观测向量
  - `InferenceRecord.get_flat_feature_names(agent_id)` — 获取展平特征名
  - `InferenceRecord.get_decision_at(t, agent_id)` — 获取指定步的决策
  - `InferenceRecord.locate_decision_step()` — 根据决策内容定位时间步
  - `AgentObservation.get_flat_vector()` — 嵌套观测→一维数组
- **输入/输出**：纯数据结构，被所有其他模块引用

### `src/module_c_counterfactual/agent_schema.py` — 智能体 Schema 契约

- **作用**：定义智能体观测空间/动作空间的固定契约，提供展平/校验/标签生成工具。
- **核心类**：
  - `AgentSchema`（冻结类）— 含 agent_id、equipment_units、observation_space、action_item_names
- **核心函数**：
  - `flatten_obs()` — 嵌套观测字典→数值向量 + 特征名列表
  - `holistic_decision_label()` — 完整决策内容→稳定 JSON 字符串标签
  - `discover_holistic_action_space()` — 从样本归纳整体动作类集合
  - `assert_same_agent_schema()` — 跨记录 schema 一致性校验
- **依赖**：被几乎所有模块引用

## 5. 模块 A：规则抽取（module_a_rules）

### 5.1 核心流程

```
collect_data     preprocess        viper           extract_rules      merge_rules
 提取样本   →   归一化+分箱   →   VIPER算法     →  DFS提取规则  →   合并冗余规则
                    │              训练决策树                        →  verify_tree_rules
                    │                               └──→  tree_plot.py  校验
                    ↓                                                    │
              agent_profile     pipeline.py（全流程编排）               PDF输出
             (预处理器持久化)
```

### 文件详解

#### `pipeline.py` — 规则抽取全流程管线

- **作用**：单标签 VIPER→规则→PDF 的端到端流水线
- **核心函数**：`run_rule_extraction_for_label()`
- **执行流程**：
  1. `collect_from_records_with_segments()` 提取样本
  2. `fit_preprocessor_with_profile()` 拟合预处理器
  3. `VIPERData.run()` 迭代训练决策树
  4. `extract_rules_from_tree()` 提取规则
  5. `merge_rules()` 合并冗余规则
  6. `verify_tree_and_rules()` 校验
  7. 导出决策树 PDF
- **输入**：`List[InferenceRecord]`, `agent_id`, 超参数
- **输出**：含准确率、规则文本、PDF 路径的字典
- **依赖**：模块 A 全部子模块

#### `collect_data.py` — 训练样本提取

- **作用**：从推理记录中提取 `(观测向量, 动作标签, 奖励)` 训练样本。
- **核心函数**：
  - `collect_from_record()` — 单条记录提取
  - `collect_from_records()` — 多条记录合并
  - `collect_from_records_with_segments()` — 带分段信息的合并提取
  - `compute_return_to_go()` — 计算 return-to-go（折扣累计奖励）用作训练权重
- **输入**：`InferenceRecord`, `agent_id`, `action_item`
- **输出**：`(X, y, rewards, feature_names)` 或五元组 `(X, y, rewards, feature_names, segment_lengths)`

#### `preprocess.py` — 特征预处理

- **作用**：特征 z-score 归一化 + 自动分箱（数值→语义标签）。
- **核心类**：`Preprocessor`
  - `fit(X)` — 学习均值和标准差
  - `transform(X)` — z-score 归一化
  - `denormalize_threshold()` — 归一化阈值→原始单位
  - `discretize_label()` — 数值→语义区间（如"低"/"高"）
- **输入**：原始特征矩阵 `(N, n_features)`
- **输出**：归一化矩阵、语义标签

#### `viper.py` — VIPER 决策树算法

- **作用**：近似 VIPER 算法（无需真实环境），用 return-to-go 加权 + 迭代重加权训练 CART 决策树。
- **核心类**：`VIPERData`
  - `run(n_iters, penalty_factor)` — 迭代训练，每轮对错误样本加权
  - `train_once(sample_weights)` — 用当前权重训练单棵树
- **核心数据结构**：`VIPERResult`（含 best_tree、best_accuracy、history）
- **算法原理**：
  1. 用 return-to-go 作为初始样本权重 → 训练决策树
  2. 找出被错分的样本 → 提高这些样本的权重（乘以 penalty_factor）
  3. 重新训练 → 重复 N 轮
  4. 取在原始权重上准确率最高的那棵树

#### `extract_rules.py` — 规则提取

- **作用**：从决策树 DFS 提取 IF-THEN 规则集。
- **核心类**：
  - `Rule` — 单条规则（conditions、action、support、confidence）
  - `RuleCondition` — 单个条件（feature_idx、op、threshold）
- **核心函数**：
  - `extract_rules_from_tree()` — DFS 遍历每一条根→叶路径
  - `rules_to_text()` — 规则列表→可读文本
- **输出**：每条规则包含条件、动作、支持度（覆盖样本数）、置信度（叶节点纯度）

#### `merge_rules.py` — 规则合并

- **作用**：合并冗余规则，减少规则数量，提高可读性。
- **核心函数**：
  - `merge_rules()` — 子集合并 + 区间合并
  - `rules_coverage()` — 评估规则集在数据上的准确率变化

#### `agent_profile.py` — 预处理器持久化

- **作用**：按智能体 + schema 指纹在本地持久化 `Preprocessor` 标尺（归一化参数、分箱边界）。
- **核心结构**：`AgentPreprocessorProfile`（含 profile_id、mean、std、auto_bins、reservoir）
- **核心函数**：
  - `fit_preprocessor_with_profile()` — profile→训练→保存 一站式
  - `load_profile()` / `save_profile()` — JSON 文件读写
- **目的**：同智能体跨任务复用标尺，防止分布漂移

#### `rule_match.py` — 规则匹配

- **作用**：将规则应用于新观测数据，输出每条规则匹配了哪些样本。
- **核心函数**：
  - `save_rules_json()` — 将规则和 coverage 写入 JSON

#### `rule_tree.py` — 规则树（可视化增强）

- **作用**：构建规则树结构，支持导出为 PDF 和可视化 diff（合并前后对比）。
- **核心函数**：
  - `build_rule_tree_from_sklearn_tree()` — sklearn tree→规则树
  - `export_rule_tree_pdf()` — 导出 PDF
  - `explain_rule_merge_steps()` — 规则合并步骤可读化

#### `verify_tree_rules.py` — 决策树校验

- **作用**：校验训练好的决策树和提取规则的一致性、覆盖率、准确率。
- **核心函数**：`verify_tree_and_rules()`

#### `train_params.py` — 训练参数解析

- **作用**：统一管理决策树训练超参数的默认值与环境变量覆盖。
- **核心函数**：`resolve_train_params()`

## 6. 模块 C：反事实推理（module_c_counterfactual）

### 6.1 核心流程

```
data_loader → inference_record → rollback → counterfactual → explain_nl → LLM润色
  加载数据      数据结构定义      定位决策步    反事实推理    自然语言渲染  (可选)
                                              │
                                    ┌─────────┼─────────┐
                                    ▼         ▼         ▼
                              local    one_step    multi_step
                            (仅π模型)  (π+T+R)   (π+T+R,多步)
                                              │
                                              ▼
                                        surrogate_bundle
                                    (π/T/R 三模型训练器)
```

### 三种反事实层级对比

| 层级 | 使用的模型 | 核心问题 | 计算量 | 输出信息 |
|------|-----------|---------|--------|---------|
| local | 仅 π（策略） | 改一个因素，决策变不变？ | 最低 | 关键特征列表 |
| one_step | π+T+R | 改完这一步奖励会不会变？ | 中 | 奖励变化 + 动作变化 |
| multi_step | π+T+R | 改完3~5步累计奖励会不会变？ | 较高 | 累计奖励变化 + 轨迹对比 |

### 文件详解

#### `counterfactual.py` — 反事实推理核心

- **作用**：实现三种层级的反事实推理算法。
- **核心数据结构**：
  - `CFContext` — 反事实上下文（record, agent_id, t_query, obs_t, action_t）
  - `LocalCFResult` — 局部反事实单特征检验结果
  - `OneStepCFResult` — 一步反事实单特征结果
  - `MultiStepCFResult` — 多步反事实单特征结果
- **核心函数**：
  - `local_counterfactual()` — 对每个特征扰动→查策略树→比较动作
  - `one_step_counterfactual()` — 扰动→π预测→T预测下一状态→R预测奖励
  - `multi_step_counterfactual()` — 扰动→π/T/R 连滚 H 步→累计奖励
  - `perturb_obs_features()` — 特征扰动（置零/替换/均值/train_mean）
  - `_surrogate_rollout()` — 用代理模型滚动推演 H 步
  - `prefilter_features_for_cf()` — L1 概率差预筛选候选特征
- **算法原理（local 为例）**：
  1. 对候选特征列表中每个特征 f：
     - 将 f 改为反事实值（如均值）
     - 其他特征保持不变 → 得到 cf_obs
  2. 将 cf_obs 送入策略决策树 → 预测 cf_action
  3. 比较 cf_action 与真实 action_t：
     - 不同 → f 是关键原因（action_changed=True）
     - 相同 → f 影响不大

#### `policy_model.py` — 策略近似模型（π）

- **作用**：用决策树/随机森林/ExtraTrees 拟合智能体的策略 `状态→动作` 映射。
- **核心类**：`PolicySurrogate`
  - `fit(record, agent_id)` — 从单条记录训练
  - `fit_records(records, agent_id)` — 从多条记录训练
  - `fit_transition_rows(rows)` — 从转移 reservoir 行训练
  - `predict(obs_vector)` — 预测动作
  - `predict_proba(obs_vector)` — 预测动作概率分布
- **三种模式**：
  - `joint` — 单棵树预测整体决策（类极不均衡时准确率可能较低）
  - `composed` — 各动作项各一棵树，预测后组装（推荐）
  - `per_item` — 调试用旧 tuple 标签
- **输入**：观测向量 `List[float]`
- **输出**：动作标签 `str` 或概率分布 `Dict[str, float]`
- **训练算法**：
  1. 遍历每步提取 `(obs_vector, decision)` 作为样本
  2. 计算 return-to-go 作为样本权重（重要决策权重大）
  3. 用带权重的 CART 决策树拟合 s→a

#### `transition_model.py` — 状态转移模型（T）

- **作用**：学习 `(s_t, a_t) → s_{t+1}` 的映射。
- **核心类**：`TransitionModel`
  - `fit(records, agent_id)` — 从推理记录训练
  - `predict(obs_vector, action_label)` — 预测下一状态
  - 使用 `RandomForestRegressor` 回归
- **两种模式**：
  - `multioutput` — 联合输出所有维度（默认）
  - `per_feature` — 每维度独立建模
- **编码**：用 `JointActionEncoder` 将动作标签编码为数值

#### `reward_model.py` — 奖励模型（R）

- **作用**：学习 `(s_t, a_t, s_{t+1}) → r_t` 的映射。
- **核心类**：`RewardModel`
  - `fit(records, agent_id)` — 从推理记录训练
  - `predict(obs_vector, action_label, next_obs_vector)` — 预测奖励
  - 使用 `GradientBoostingRegressor` 回归

#### `surrogate_bundle.py` — 三模型联合训练器

- **作用**：为一步/多步反事实统一训练 π/T/R 三个代理模型。
- **核心类**：`SurrogateBundle`
  - `fit(records, agent_id)` — 一次性训练三个模型 + 计算特征均值
  - `fit_from_transition_rows()` — 从转移 reservoir 行重训（增量用）
- **核心数据结构**：`SurrogateBundle`（policy, transition, reward, obs_feature_means, feature_names）
- **关键特性**：
  - 自动策略模式选择（auto: joint vs composed CV 选优）
  - 策略树自动调参（CV 搜索深度/叶节点）
  - 转移模型自动调参 + 标准化评估（N-MSE/MAE）
  - Holdout 验证计算（按仿真局划分）

#### `causal_effect.py` — 因果效应量计算

- **作用**：从 K 采样反事实数据集中计算机械论/目的论因果效应（对应论文表 2）。
- **核心函数**：
  - `mechanistic_effect()` — 用分类器拟合 `state_features → query_happened`，特征重要性排序
  - `teleological_effect()` — 计算 `mean(reward|happened) - mean(reward|not_happened)`
- **核心数据结构**：`CausalFactor`（name, effect, rank）

#### `cf_dataset.py` — 反事实数据集生成

- **作用**：在观测空间上对代理模型做 K 次采样，生成表 1 格式的反事实数据集。
- **核心类**：`CFSample`（state_features, reward_scalar, query_happened）
- **核心函数**：`generate_cf_dataset()`
  - 对原始观测施加高斯噪声（幅度可调）
  → 策略采样动作 → 转移推下一步 → 奖励计算
  → 重复 K 次
- **输入**：`CFContext`, `SurrogateBundle`, K, horizon, noise_scale
- **输出**：`List[CFSample]`

#### `cema.py` — CEMA 顶层编排器

- **作用**：CEMA（Counterfactual Effect-size Model for Agents）的高层封装，统一调度 local/one_step/multi_step/K 采样。
- **核心类**：`CEMA`
  - `fit_models(agent_id)` — 训练 SurrogateBundle
  - `explain_at(agent_id, t_query, level)` — 按时间步解释
  - `explain_by_action(agent_id, action, occurrence)` — 按动作标签解释
- **输出**：`CEMAResult`（含机械性文本、目的性文本）

#### `rollback.py` — 决策回溯

- **作用**：根据用户输入 `(agent_id, decision_content)` 在记录中定位时间步，构建 `CFContext`。
- **核心类**：`ObservationRollback`
  - `from_frontend_input()` — 决策内容 + 可选步号 → CFContext
  - `build_context()` — 已知 `(agent_id, t_query)` → CFContext

#### `explain_nl.py` — 自然语言解释渲染

- **作用**：将反事实推理的数值结果渲染为可读的中文自然语言解释。
- **核心函数**：
  - `render_cf_explanation()` — local 层级的机械性/目的性解释
  - `render_one_step_explanation()` — one_step 层级的解释
  - `render_multi_step_explanation()` — multi_step 层级的解释
  - `render_k_sampling_explanation()` — K 采样+因果效应量的解释
  - `attach_natural_language_qa()` — 问答式解释
- **输出字典键**：`mechanistic`, `teleological`, `headline`, `nl_question`, `nl_answer_mechanistic`, `nl_answer_teleological`, `key_features`

#### `llm_explain.py` — LLM 解释润色（可选）

- **作用**：用预训练语言模型（本地 transformers 或 OpenAI 兼容 API）润色反事实解释文本。
- **核心函数**：`enhance_cf_explanation()`
- **两种后端**：
  - 本地 transformers（通过 `verify_llm_model.py` 验证）
  - OpenAI 兼容 API
- **开关**：环境变量 `ANALYSIS_LLM_EXPLAIN`

#### `action_encoding.py` — 动作编码

- **作用**：将联合动作字符串编码为数值，供转移/奖励模型使用。
- **核心类**：`JointActionEncoder`（封装 `LabelEncoder`）

#### `surrogate_cache.py` — 代理模型缓存

- **作用**：进程内缓存 + 磁盘 profile 持久化 SurrogateBundle/PolicySurrogate，避免重复训练。
- **核心函数**：
  - `get_or_fit_surrogate_bundle()` — 查内存→查磁盘→训练
  - `get_or_fit_policy_surrogate()` — 同上，仅策略模型

#### `agent_surrogate_profile.py` — 代理模型 profile

- **作用**：按智能体 + task 持久化 SurrogateBundle 的 profile（含训练样本 reservoir 和模型参数）。
