### 博弈约简   

修改成基于观测空间的博弈约简

注：单智能体，约简决策步

博弈约简和基于博弈约简的溯因分析不是完全一样，前者就是做博弈约简，给关键要素，后面的还要做决策的分析性解释

博弈约简其实就是   原始场景里有关的对象太多了，我先找出真正影响我决策的那些，再把其余影响很小的对象压缩掉或合并掉。核心就在于，把周围和自身的影响决策的因素收缩一下，他不解释为什么，只做约简影响要素。

而且约简的通常都是邻居的状态和行为，保留中心智能体本身的状态。

#### 算法分析步骤：

1. 拿到要分析的对象，也就是中心智能体的某一时刻的某一个单位的动作，比如`蓝方战机1在时刻t为什么做这个动作`

2. 收集当时的邻居集合

3. 把邻居集合变成一个特征集合，也就是把邻居对智能体的影响要素结构化，也就是说，记的是这个邻居与中心智能体之间的关系，比如：当前邻居的类型，相对距离，相对高度，是否可见等

4. 然后再开始进行博弈约简，按照理解，可以做成简单版和升级版

   - ##### 简单版：做成基于规则的博弈约简

     ​    直接根据数据，定义几个规则，相对距离近的敌机，我认为他的威胁度高，相对距离远的友机，我认为对逃逸行为的影响度高，也就是，定义几个与当前动作最相关的规则，基于这个，把其他不重要的约简掉然后就是返回关键特征了，比如说最近敌机距离，高威胁敌机数量等，让用户知道做出决策的什么是关键要素

   - ##### 升级版：基于模型的博弈约简（也就是做一个近似CFMQ）

     ​    CFMQ的核心思想是，把邻居做成一个聚合整体，然后只看整体和中心智能体之间的交互影响，而聚合整体中，也会有关键的邻居和不关键的邻居，这部分的话，就需要算一个邻居的权重，这也就是最重要的部分：因果权重。人话解释就是`如果把某个邻居拿掉或替换掉，我的决策会不会明显变化`

     ​	然后就需要训练一个中心决策的近似器，因为需要直到，在替换邻居之后，中心体动作的变化来反映这个邻居的权重

     ​	而且如果要用CFMQ的话其实还挺复杂的：

     ​	要构造邻居的集合表示，还有拿到中心体的基准动作分布（即动作的样本数占比）、然后替换邻居，用近似器跑中心智能体的决策，然后拿到动作分布， 然后用KL 散度量化变化（这个就是把某个邻居拿出来看时，中心智能体策略变化有多大的具体衡量值）、然后就是算因果权重（就是KL散度的归一化），最后才是做约简，简单点就是保留topK，难一点就是像论文中说的构造加权合并邻居
   
5. 如果还需要做溯因分析的话，还需要去根据博弈约简的结果，做解释，这种解释为组合动作解释，大体格式为，中心智能体做了什么动作，是由于

### 反事实推理

注：修改成基于观测空间的反事实推理

反事实推理就是把真实的决策拿出来，然后询问，如果当时条件不一样了，智能体还是否会这么做

溯因分析中的反事实推理是通过比较反事实的情况，解释为什么当时的决策的原因

#### 算法实现分析步骤：

1. 选择要解释的决策

2. 回溯到决策之前的状态

3. 选择候选原因

4. 修改状态       注：选择候选原因和修改状态不知道是人为选择的，还是用一个模型自己选择。

5. 进行反事实推理 ，这部分可以递进实现，从简单到难，局部反事实，一步反事实，和多步反事实

   ##### 局部反事实：  （解释：为什么这一步会这么选择）

   ​	只需要一个策略近似模型，最最简单的就是决策树，输入当前状态（修改后的），输出动作，

   每次修改原状态中，选择的候选原因中的一个状态，看动作是否改变，如果改变，说明修改的候选原因就是强解释因子，然后就可以回答，为什么这一步会这么选择

   ##### 一步反事实：（进一步解释：如果当时条件变了，这一步动作会不会变，以及下一步局势会不会更好/更坏）

   ​	需要三个模型，策略近似模型，状态转移模型，奖励模型

   ​	策略近似模型     就是决策树或者分类器

   ​	状态转移模型     就是算下一个状态的，算一个`s_t, a_t) -> s_(t+1)`，如果有邻居信息一起算，肯定是								最好的

   ​	奖励模型            就是算看这么做之后，奖励值是否会变化，算一个`(s_t, a_t, s_(t+1)) -> r_t`

   ​	大致流程的话，就是

   ```
   取真实的状态  s_t
   然后改一个因素，得到反事实状态 s'_t
   用策略模型算新动作 a'_t
   用状态转移模型推下一个状态 s'_(t+1)
   用奖励模型算 r'
   比较a'_t 和 a_t ， s'_(t+1) 和 s_(t+1)    r_t 和 r'_t
   ```

   ##### 多步反事实：（近似CEMA思想）

   ​	CEMA 是一个多智能体场景里的因果解释框架。核心就是三步，回滚，前向模拟，比较

   然后给出两种解释，机械性解释和目的性解释

   机械性解释就是`是什么导致它这么做`

   目的性解释就是`它这么做是为了什么结果`

   ​	这个和一步反事实的区别就是，在修改候选原因的时候，可以选择一个或者一组，然后状态转移模型可以推多步，然后进行比较的时候，累计比较后续奖励，后续的动作序列，以及最终的结果

6. 比较真实世界和反事实世界，然后解释原因。就是拿上一步的结果，直接解释就行，这个可以到时候套一个模板，`因为xxx，所以决策选择了xx`，或者就是像CEMA一样，给出两种解释。

决策树的偏差：

决策树这个算法本身的需求是把智能体内部的决策策略从黑盒拆解为白盒，让用户可以近似的去理解智能体是如何决策的，说人话，就是，决策树是一个用户输入状态，就能得到一个动作，这个动作是近似模拟智能体会做出的决策。

也就是说，这个动作一定是根据输入状态直接产生的，在做出这个动作之前，状态一定还是输入的状态。

那么如果把决策树的节点定义为状态，线定义为动作，状态根据动作改变，产生下一个状态，这种就无法解释需求，也无法解释为什么决策树从根到叶子是一条决策规则。

在我多次读了论文后，我认为，决策树节点的本质上是在记录：这里按什么条件分、分完后样本分布如何、最终应该往哪边走。决策树节点分成两类，中间节点和叶子节点
中间节点的作用就是根据某个条件，把样本继续往下分

叶子节点则是不再继续分裂，直接给出最终类别/动作。

内部节点主要包含：划分特征、划分阈值、样本数、类别分布、纯度、当前主类别。
叶子节点主要包含：样本数、类别分布、纯度和最终预测动作。

节点：对某个状态特征的判断

边：判断结果（是/否，或小于/大于阈值）

叶子节点：最终输出动作



观测空间和动作空间在智能体设计好的时候就已经定好了，这个智能体，无论在什么场景下都超脱不了这两个空间

我们在进行溯因分析的时候，实际上就是基于智能体进行分析的，分析的一定是一个智能体为什么做出了某一个决策

规则抽取和博弈约简都好说，直接对观测空间进行操作，要么直接把决策树抽出来，要么就是把观测空间约成几个关键的即可

那么反事实推理呢，既然要做反事实推理，那就要回到做出决策之前，而且我们是对于智能体进行决策的，一个智能体在多局中的推理数据可能有很多个，那么这个智能体的决策次数可能会堆成很大，但是如果只选动作空间的一个动作的话，可能又无法确定当时的状态，那么用户在前端选择的数据应该是什么样子的呢

智能体（肯定是一个），限定局数（或者说仿真id），具体决策内容，然后就可以定位到一条推理数据中的决策中找到做出所选动作的内容，就可以定位到某一个状态了
