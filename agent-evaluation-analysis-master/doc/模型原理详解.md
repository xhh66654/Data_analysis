## 1. 模型体系总览

本系统使用 **代理模型（Surrogate Model）** 方法解释智能体决策行为。核心思想是：用可解释的简单模型（决策树、随机森林）模仿黑盒智能体的行为，然后用这些简单模型做反事实推理。

### 三代理模型

| 模型 | 符号 | 映射关系 | 算法 | 用途 |
|------|------|---------|------|------|
| 策略近似 | π (Policy) | `s_t → a_t` | CART 决策树 / RF / ET | 预测智能体在当前态势下的动作 |
| 状态转移 | T (Transition) | `(s_t, a_t) → s_{t+1}` | 随机森林回归 | 预测执行动作后的下一状态 |
| 奖励模型 | R (Reward) | `(s_t, a_t, s_{t+1}) → r_t` | GBDT 回归 | 预测执行动作获得的奖励 |

### 全景数据流

```
真实环境仿真
     │
     ▼
推理数据 ──→ 数据加载 ──→ 训练代理模型 ──→ 反事实推理 ──→ 自然语言解释
JSON/Doris    data_loader   π/T/R 三模型    特征扰动+预测     explain_nl
                              │
                          surrogate_bundle
                          (统一训练入口)
```

## 2. 策略近似模型 — PolicySurrogate（π）

### 2.1 模型原理

**目的**：学习映射 `观测状态 s_t → 智能体决策 a_t`，得到一个可解释的策略近似。

**为什么用决策树**：
- 决策树天生就是 IF-THEN 规则集合，易于解释
- 可以方便地做反事实推理（改一个输入特征，看输出怎么变）
- 训练速度快，适合多次迭代

### 2.2 训练算法

#### 步骤 1：样本提取

从推理记录 `InferenceRecord` 中提取训练样本：

```
遍历每一步 t：
    obs_t = record.get_obs_vector(t, agent_id)   // 观测向量
    dec_t = record.get_decision_at(t, agent_id)   // 决策对象
    if obs_t 和 dec_t 都存在：
        X.append(obs_t)                           // 特征
        y.append(holistic_label(dec_t.content))   // 标签
        rewards.append(record.rewards[t])         // 奖励
```

**输入数据示例**（歼-20，8个特征）：

| 特征 | 值 | 含义 |
|------|-----|------|
| 自身状态.血量 | 0.800 | 血量百分比 |
| 自身状态.速度_马赫 | 1.200 | 速度（马赫） |
| 飞行状态.高度_km | 7.500 | 高度（公里） |
| 敌机距离.水平距离_km | 40.000 | 水平距离 |
| 敌机距离.高度差_km | 0.500 | 高度差 |
| 机动状态.燃油剩余 | 0.600 | 燃油剩余 |
| 敌机状态.存活 | 1.000 | 存活标记 |
| 敌机状态.锁定中 | 0.000 | 锁定标记 |

**输出标签示例**：

```
{"机动控制": "追击", "武器控制": "不发射", "雷达开关控制": "关", "雷达方向控制": "正前方"}
→ 编码为 holistic JSON 标签字符串
```

#### 步骤 2：Return-to-Go 权重计算

每条样本的权重 = 从该步到仿真结束的累计奖励：

```
设 rewards = [r_0, r_1, ..., r_{T-1}]
rtg[T-1] = r_{T-1}
rtg[t]   = r_t + rtg[t+1]   （从后向前递推）
权重 = min-max 归一化后的 rtg（保证全为正数）
```

**意义**：后续收益大的决策步骤权重更高，训练时更关注"关键决策"。

#### 步骤 3：训练分类器

支持三种模式：

**模式 1：joint（单树整体决策）**

```
训练单棵 CART 决策树：
    输入：X（观测矩阵），y（整体决策标签）
    权重：return-to-go
    准则：基尼指数（Gini impurity）
    输出：单棵决策树 _clf
```

**模式 2：composed（分项组装，推荐）**

```
对每个动作项 item（如"机动控制"、"武器控制"）：
    提取该动作项的标签 y_item
    训练一棵独立的决策树 clf_i
预测时：各树独立预测 → 组装为完整 JSON 标签
```

**模式 3：per_item（调试用）**

与 composed 类似，但输出旧 tuple 字符串格式。

### 2.3 预测流程

```
给定观测向量 obs（List[float]）：
1. 若启用 z-score 归一化，先 transform
2. 若 joint 模式：_clf.predict(obs) → 直接输出动作标签
3. 若 composed 模式：
   for each item, clf_i in _item_clfs:
       pred[item] = clf_i.predict(obs)
   → 组装为 holistic JSON 字符串
4. 返回动作标签
```

### 2.4 概率预测（predict_proba）

用于计算反事实推理中的"变化幅度"（prob_delta_l1）。

- **joint 模式**：直接返回决策树的类别概率分布
- **composed 模式**：各动作项概率的笛卡尔积近似联合分布

```
P(联合动作 A) = Π P(动作项 i = value_i)
假设各动作项条件独立
```

### 2.5 超参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| max_depth | 6 | 树最大深度（可通过 CV 调优） |
| min_samples_leaf | 2 | 叶节点最小样本数 |
| mode | composed | joint / composed / per_item |
| estimator | tree | tree / et (ExtraTrees) / rf (RandomForest) |
| n_estimators | 150 | 集成方法树数量 |
| class_weight | balanced | 类别权重调整 |

## 3. 状态转移模型 — TransitionModel（T）

### 3.1 模型原理

**目的**：学习映射 `(s_t, a_t) → s_{t+1}`，即在当前状态下执行某动作后，环境会变成什么样。

**为什么需要 T 模型**：反事实推理不仅要问"决策会不会变"，还要问"决策变了之后后续态势会怎么演变"，这需要 T 模型来推演。

### 3.2 数据构造

```
遍历每一步 t（除最后一步）：
    obs_t     = record.get_obs_vector(t, agent_id)
    obs_{t+1} = record.get_obs_vector(t+1, agent_id)
    action    = joint_action_label(dec_t.content)
    
    特征 X = obs_t + encode(action)     ← 观测 + 动作编码
    标签 y = obs_{t+1}                   ← 下一时刻观测
```

### 3.3 动作编码（JointActionEncoder）

```
输入：联合动作标签字符串
    如：'{"机动控制": "追击", "武器控制": "不发射", ...}'
处理：LabelEncoder 映射为数值
    如：标签 → 0, 1, 2, ...
输出：数值编码（float）

未见过的标签 → 映射为 -1（未知类别）
```

最终特征向量构造：

```
X = [obs_0, obs_1, ..., obs_{n-1}, action_encoded]
```

### 3.4 训练与预测

**算法**：`RandomForestRegressor`（随机森林回归）

```
训练：
    X.shape = (n_samples, n_features + 1)    ← 观测维数 + 动作编码
    y.shape = (n_samples, n_features)         ← 与观测同维
    
预测：
    输入：[obs_t 向量, action_encoded]
    输出：obs_{t+1} 向量（预测的下一时刻观测）
```

**两种模式**：

| 模式 | 建模方式 | 优点 | 缺点 |
|------|---------|------|------|
| multioutput | 单模型联合输出所有维 | 简单快速 | 特征间关系隐式 |
| per_feature | 每维独立建模 | 灵活、可并行 | 训练成本高 |

### 3.5 输入输出示例

```
输入：
    obs_t     = [0.800, 1.200, 7.500, 40.000, 0.500, 0.600, 1.000, 0.000]
    action    = "机动控制=追击,雷达方向控制=正前方,雷达开关控制=关,武器控制=不发射"
    → encode(action) = 3.0
    X = [0.800, 1.200, 7.500, 40.000, 0.500, 0.600, 1.000, 0.000, 3.000]

输出：
    obs_{t+1} = [0.750, 1.150, 7.800, 38.000, 0.600, 0.580, 1.000, 1.000]
```

## 4. 奖励模型 — RewardModel（R）

### 4.1 模型原理

**目的**：学习映射 `(s_t, a_t, s_{t+1}) → r_t`，即当前状态采取某动作后能得到多少奖励。

### 4.2 数据构造

```
遍历每一步 t：
    obs_t     = record.get_obs_vector(t, agent_id)
    obs_{t+1} = record.get_obs_vector(t+1, agent_id)  （最后一步无下一状态）
    action    = encode(action_label)
    reward    = record.rewards[t]
    
    特征 X = [obs_t, action_encoded, obs_{t+1}]
    标签 y = reward
```

### 4.3 训练与预测

**算法**：`GradientBoostingRegressor`（梯度提升回归树）

```
训练：
    X.shape = (n_samples, 2 × n_features + 1)
    y.shape = (n_samples,)
    
预测：
    输入：[obs_t, action_encoded, obs_{t+1}]
    输出：标量奖励值（float）
```

### 4.4 输入输出示例

```
输入：
    obs_t      = [0.800, 1.200, 7.500, 40.000, ...]
    action_enc = 3.0
    obs_{t+1}  = [0.750, 1.150, 7.800, 38.000, ...]
    
输出：
    reward = 0.650（标量）
```

## 5. VIPER 决策树算法

### 5.1 算法背景

VIPER（Verifiability via Iterative Policy Extraction）是一种从强化学习策略中提取可解释决策树的算法。本系统实现了**近似版 VIPER**，无需真实环境交互，仅从离线推理数据中训练。

### 5.2 算法流程

```
输入：
    X_raw      — 原始观测矩阵 (N, D)
    y          — 动作标签 (N,)
    rewards    — 奖励序列 (N,)
    n_iters    — 迭代轮数（默认 5）
    penalty    — 错分惩罚因子（默认 2.0）

步骤：
    1. 用 Preprocessor 对 X_raw 做 z-score 归一化 → X
    2. 计算 return-to-go 作为初始样本权重 w
    3. 用 (X, y, w) 训练第一棵 CART 决策树
    4. 计算在原始权重上的准确率 acc
    5. 对每轮迭代：
        a. 用当前权重训练决策树
        b. 找出被当前树错分的样本
        c. 提高这些样本的权重：w[i] *= penalty
        d. 重新归一化权重
        e. 用新权重重新训练
        f. 计算在新树在原始权重上的准确率
        g. 保留准确率最高的那棵树
    6. 返回所有迭代中准确率最高的决策树
```

### 5.3 算法示意图

```
轮次 1:  w = rtg                → 训练树1 → acc=0.82 → 保留
轮次 2:  w = w * penalty(错分)  → 训练树2 → acc=0.85 → 保留（更好）
轮次 3:  w = w * penalty(错分)  → 训练树3 → acc=0.83 → 保留树2
...  
最终：返回 acc 最高的树（树2）
```

### 5.4 超参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| n_iters | 5 | 迭代轮数，越多越准但越慢 |
| penalty_factor | 2.0 | 错分样本权重放大倍数 |
| max_depth | 6 | 决策树最大深度 |
| min_samples_leaf | 2 | 叶节点最小样本数 |

### 5.5 模块 A 流程（与 VIPER 的关系）

```
module_a_rules 完整流程：

colect_data → Preprocessor → VIPER.run → extract_rules → merge_rules → verify
  提取样本      归一化/分箱     迭代训练     DFS 提取    合并冗余      校验
                                │            IF-THEN
                                ▼
                            决策树 PDF
```

规则提取示例输出：

```
【规则 1】
IF 飞行状态.高度_km <= 较低（7.51）
     AND 机动状态.燃油剩余 <= 低（0.59）
THEN [('机动控制','追击'), ('武器控制','不发射'), ('雷达开关控制','关'), ('雷达方向控制','正前方')]
（支持度: 12，置信度: 1.00）
```

## 6. SurrogateBundle — 三模型联合训练器

### 6.1 作用

SurrogateBundle 是 one_step 和 multi_step 反事实推理的基础设施，一次训练三个模型（π/T/R）为后续推理复用。

### 6.2 训练流程

```
SurrogateBundle.fit(records, agent_id):
    1. 校验所有记录的 schema 一致性
    2. 选择策略模式（auto/joint/composed）
       - auto：用 CV 比较 joint 和 composed 的准确率
    3. 策略树自动调参（CV 搜索）
       - 搜索 max_depth ∈ {base-1, base, base+1, base+2}
       - 搜索 min_samples_leaf ∈ {1, 2, base±1, base+2, base+5}
    4. 训练 PolicySurrogate（π）
    5. 计算训练集特征均值（用于 train_mean 扰动策略）
    6. 训练 TransitionModel（T）
       - 可选自动调参（网格搜索 n_estimators/max_depth/min_samples_leaf）
       - 计算标准化评估指标（N-MSE, MAE）
    7. 训练 RewardModel（R）
    8. 计算 holdout 验证指标（按仿真局划分）
    9. 返回 SurrogateBundle 实例
```

### 6.3 核心数据结构

```python
@dataclass
class SurrogateBundle:
    policy: PolicySurrogate       # 策略模型 π
    transition: TransitionModel   # 转移模型 T
    reward: RewardModel           # 奖励模型 R
    obs_feature_means: List[float]  # 各特征均值（扰动参考）
    feature_names: List[str]       # 特征名列表
    n_training_transitions: int    # 训练样本数
    training_debug: Optional[Dict] # 训练调试信息
```

### 6.4 缓存机制

SurrogateBundle 通过 profile 机制缓存：`surrogate_cache.py`

```
get_or_fit_surrogate_bundle():
    1. 查进程内内存缓存（dict）→ 命中直接返回
    2. 查磁盘 profile（JSON 文件）→ 命中反序列化返回
    3. 都没有 → 调用 SurrogateBundle.fit() 训练新模型
    4. 持久化到磁盘 profile
    5. 存入内存缓存
    6. 返回 (bundle, 是否缓存命中, profile版本)
```

## 7. Preprocessor — 特征预处理器

### 7.1 作用

- z-score 归一化：消除特征量纲差异
- 自动分箱：将连续数值翻译为语义标签（"低"/"中"/"高"）

### 7.2 归一化

```
z-score 归一化：
    x_scaled = (x - mean) / std
    
其中：
    mean = (1/N) * Σx_i
    std  = sqrt((1/N) * Σ(x_i - mean)²)
```

### 7.3 自动分箱

```
分箱方法：等分位数分箱（pandas qcut）
    每个特征分成 3 个区间（低/中/高）
    边界 = 分位数 [0, 1/3, 2/3, 1]

语义标签映射：
    区间 0（最低 1/3）→ "{特征名}.低"
    区间 1（中间 1/3）→ "{特征名}.中"  
    区间 2（最高 1/3）→ "{特征名}.高"

示例：
    特征 "飞行状态.高度_km" 的分箱边界 = [5.0, 7.5, 10.0, 15.0]
    值 7.0 → "飞行状态.高度_km.低"
    值 8.0 → "飞行状态.高度_km.中"
    值 12.0 → "飞行状态.高度_km.高"
```

### 7.4 阈值反归一化

```
决策树分裂阈值在归一化空间，展示时需要还原为原始单位：
    original_threshold = threshold * std + mean
    
示例：
    归一化阈值 = -0.500
    mean(高度_km) = 10.0, std(高度_km) = 5.0
    原始阈值 = -0.500 × 5.0 + 10.0 = 7.5 km
    
规则展示：
    IF 飞行状态.高度_km <= 较低（7.51）
```

### 7.5 Profile 持久化

归一化参数和分箱边界按智能体 + schema 指纹持久化到 JSON 文件：

```json
{
    "profile_id": "agent_1_fp_a1b2c3d4",
    "version": 1,
    "schema_fingerprint": "sha256:...",
    "mean": [0.5, 1.0, 8.0, ...],
    "std": [0.2, 0.3, 2.0, ...],
    "auto_bins": {
        "飞行状态.高度_km": [5.0, 7.5, 10.0, 15.0],
        ...
    },
    "reservoir": [[...], ...]  // 最近 N 条样本
}
```

## 8. 反事实推理算法

### 8.1 什么是反事实推理？

反事实推理回答"如果当时不一样，结果会怎样"的问题：

```
真实世界：t=3 时刻，敌机距离=40km，智能体选择了"规避"
反事实问：如果当时敌机距离是 85km（而不是 40km），智能体会选"规避"还是"追击"？
```

### 8.2 特征扰动策略

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| zero | 将特征值置为 0 | 快速检验，特征 0 无特殊含义时慎用 |
| train_mean | 替换为训练集该特征均值 | 推荐策略（默认），反映"典型值" |
| replace | 使用提供的参考值替换 | 自定义参考场景 |
| delta_up | 特征值增大 50%（至少+1） | 检验正向影响 |
| delta_down | 特征值减小 50%（至少-1） | 检验负向影响 |

### 8.3 局部反事实（local）

**算法流程**：

```
local_counterfactual(ctx, policy_model):
    输入：
        ctx.obs_t      — 真实观测向量
        ctx.action_t   — 真实动作
        feature_names  — 特征名列表
    
    对每个候选特征 f in feature_names：
        1.  perturbation: 将 obs_t 中的 f 改为反事实值
            → cf_obs（其他特征不变）
        2.  用 policy_model.predict(cf_obs) 预测反事实动作 cf_action
        3.  比较 cf_action 与 ctx.action_t：
            - 不同 → action_changed=True（f 是关键原因）
            - 相同 → action_changed=False（f 影响不大）
    
    输出：List[LocalCFResult]
        - candidate_feature: "敌机距离.水平距离_km"
        - original_action: "机动控制=规避,..."  
        - cf_action: "机动控制=追击,..."
        - action_changed: True
        - change_score: 1.0
```

**核心代码**：

```python
# counterfactual.py 第 202-330 行
for feat in candidate_features:
    cf_obs = perturb_obs_features(
        obs_vector=ctx.obs_t,
        feature_names=feature_names,
        candidate_features=[feat],
        strategy=perturb_strategy,
        ref_value=ref_value,
    )
    cf_action = policy_model.predict(cf_obs)
    action_changed = (cf_action != ctx.action_t)
    results.append(LocalCFResult(
        candidate_feature=feat,
        original_action=ctx.action_t,
        cf_action=cf_action,
        action_changed=action_changed,
        change_score=1.0 if action_changed else 0.0,
        change_score_mode="action_change",
        cf_obs=cf_obs,
    ))
```

### 8.4 一步反事实（one_step）

**与 local 的区别**：local 只看动作是否变化，one_step 额外预测"执行这个动作后一步的奖励变化"。

```
one_step_counterfactual(ctx, bundle):
    输入：
        ctx.obs_t      — 真实观测 (t 时刻)
        ctx.action_t   — 真实动作
        bundle         — SurrogateBundle（π+T+R）
    
    对每个候选特征 f：
        1. 扰动 f → cf_obs
        2. π 预测动作：cf_action = bundle.policy.predict(cf_obs)
        3. T 预测下一状态：cf_next = bundle.transition.predict(cf_obs, cf_action)
        4. R 预测奖励：cf_reward = bundle.reward.predict(cf_obs, cf_action, cf_next)
        5. 对比真实奖励：reward_delta = cf_reward - real_reward[t]
    
    输出：List[OneStepCFResult]
        - candidate_feature: "敌机距离.水平距离_km"
        - original_action: "机动控制=规避"
        - original_reward: 0.500
        - cf_action: "机动控制=追击"
        - cf_reward: 0.850
        - reward_delta: +0.350  ← 改了这个特征后模型认为奖励会更高
        - action_changed: True
```

### 8.5 多步反事实（multi_step）

**与 one_step 的区别**：one_step 只看 1 步，multi_step 连滚 H 步（3~5步），看累计奖励变化。

```
multi_step_counterfactual(ctx, bundle, horizon=5):
    1. 事实基线：
        从仿真记录读出从 t 到 t+H-1 的真实动作序列 + 累计奖励
    2. 对每个特征 f：
        a. 扰动 f → cf_obs（反事实起始态势）
        b. 用 π/T/R 连滚 H 步 → 反事实轨迹
        c. 计算反事实累计奖励
        d. 对比事实累计奖励：reward_delta
    
    滚动过程（_surrogate_rollout）：
        obs = cf_obs
        for step in range(H):
            action = bundle.policy.predict(obs)
            next_obs = bundle.transition.predict(obs, action)
            reward = bundle.reward.predict(obs, action, next_obs)
            cum_reward += reward
            obs = next_obs
    
    输出：List[MultiStepCFResult]
        - candidate_feature: "敌机距离.水平距离_km"
        - horizon: 5
        - original_action_seq: ["规避","规避","规避","追击","追击"]
        - original_cumulative_reward: 2.500
        - cf_action_seq: ["规避","规避","追击","追击","追击"]
        - cf_cumulative_reward: 3.200
        - reward_delta: +0.700
```

### 8.6 特征预筛选

对于高维观测空间，在正式反事实前先用 L1 概率差进行预筛选：

```python
def prefilter_features_for_cf(ctx, policy, candidate_features, top_k=12):
    对每个候选特征 f：
        cf_obs = perturb_obs_features(ctx.obs_t, ..., [f])
        base_proba = policy.predict_proba(ctx.obs_t)    # 原始概率分布
        cf_proba = policy.predict_proba(cf_obs)         # 扰动后概率分布
        delta = L1(base_proba, cf_proba)                # 概率分布变化幅度
    保留 delta 最大的 top_k 个特征 → 做正式反事实推理
```

## 9. K 采样因果效应量（Causal Effect）

### 9.1 核心思想

不同于逐特征确定性扰动（修改一个特征到固定值），K 采样方法对**所有特征同时施加随机噪声**，生成 K 个反事实样本，然后用统计方法衡量因果效应。

### 9.2 数据集生成（cf_dataset.py）

```
generate_cf_dataset(ctx, bundle, K=100):
    输入：
        ctx.obs_t      — 原始观测
        bundle         — π/T/R 三模型
        K              — 采样次数
        noise_scale    — 噪声幅度（默认 0.1）
        horizon        — 滚动步数
        reward_mode    — "step" 或 "cumulative"
    
    重复 K 次：
        1. 对原始观测各维施加高斯噪声：
           cf_obs[i] = obs[i] + N(0, noise_scale × max(|obs[i]|, 1.0))
        2. 按策略概率分布采样动作：
           action = sample_from_policy(bundle.policy, cf_obs)
        3. 记录 query_happened = (action == ctx.action_t)
        4. 计算奖励（单步或累计）
    
    输出：List[CFSample]
        - state_features: 扰动后的观测向量
        - reward_scalar: 奖励值
        - query_happened: 是否仍做出了查询的动作
```

### 9.3 机械论效应（mechanistic_effect）

**问题**：哪些状态特征是导致"做出查询动作"的原因？

```python
def mechanistic_effect(samples, feature_names):
    1. 构建分类问题：
       X = samples.state_features（扰动后观测）
       y = samples.query_happened（是否做出了查询动作）
    2. 用 RandomForestClassifier 拟合 X → y
       样本数 < 20 时改用 LogisticRegression
    3. 取特征重要性作为因果效应量
    4. 按效应量降序排列
    
    输出：List[CausalFactor]
        - name: "敌机距离.水平距离_km"
        - effect: 0.350（特征重要性）
        - rank: 1
```

### 9.4 目的论效应（teleological_effect）

**问题**：做出查询动作的样本，和没做出查询动作的样本，奖励均值差多少？

```python
def teleological_effect(samples):
    happened_rewards = [s.reward_scalar for s in samples if s.query_happened]
    not_happened_rewards = [s.reward_scalar for s in samples if not s.query_happened]
    delta = mean(happened_rewards) - mean(not_happened_rewards)
    
    输出：List[CausalFactor]
        - name: "reward_scalar"
        - effect: +0.250（做出查询动作的样本平均多 0.25 分）
        - rank: 1
```

### 9.5 与局部反事实的对比

| 特性 | 局部反事实 | K 采样 |
|------|-----------|--------|
| 扰动方式 | 每次改一个特征到固定值 | 所有特征同时加随机噪声 |
| 模型使用 | π（local）或 π+T+R | π+T+R |
| 统计量 | 动作是否变化 | 特征重要性 + 奖励均值差 |
| 计算量 | O(特征数) | O(K × horizon) |
| 优点 | 逐个归因，直觉清晰 | 联合分布采样，统计严谨 |
| 适合场景 | 特征数少（<20） | 特征数多或需要稳健估计 |

## 10. CEMA 编排器

### 10.1 作用

CEMA（Counterfactual Effect-size Model for Agents）是反事实推理的高层编排入口，封装了训练、定位、推理、解释的完整流程。

### 10.2 API 接口

```python
# 1. 初始化
cema = CEMA(record=inference_record)

# 2. 训练代理模型
cema.fit_models(agent_id=1)

# 3. 按时间步解释
result = cema.explain_at(
    agent_id=1,
    t_query=3,
    level="one_step",
)

# 4. 按动作标签解释
result = cema.explain_by_action(
    agent_id=1,
    action='机动控制=规避,雷达方向控制=正前方,...',
    occurrence=0,  # 第几次出现
    level="multi_step",
)
```

### 10.3 输出结构（CEMAResult）

```python
@dataclass
class CEMAResult:
    query_agent_id: int           # 被解释的智能体
    t_query: int                  # 时间步
    original_action: Any          # 原始动作
    level: str                    # local / one_step / multi_step
    detail: Any                   # 推理细节（LocalCFResult 列表等）
    mechanistic_text: str         # 机械性解释文本
    teleological_text: str        # 目的性解释文本
    extra: Optional[Dict]         # 扩展信息
```
