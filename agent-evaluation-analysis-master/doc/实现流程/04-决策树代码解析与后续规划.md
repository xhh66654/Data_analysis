# 决策树代码解析与后续规划

## 1. 先说结论

目前这个项目里，和决策树直接相关的代码已经完成了一个比较清晰的“第一阶段实验版”：

1. 能从 Excel 数据里读取状态和动作标签。
2. 能训练一个 `DecisionTreeClassifier` 做动作分类。
3. 已经尝试了两种特征方案：
   - 相关性筛选前 10 个特征；
   - 手工挑选关键特征，再额外构造 `速度差`。
4. 能把树导出成 PDF / DOT 可视化。
5. 能把节点信息导出成 `csv/xlsx`，便于后续做规则分析。

换句话说，现在已经不再是“从零开始”，而是已经走到了：

**数据读入 -> 特征选择/构造 -> 决策树训练 -> 基础评估 -> 树可视化 -> 节点表导出**

但还没有真正进入更完整的“论文级/项目级”第二阶段：

- 规则自动提取与清洗
- 多组实验对比
- 剪枝 / 调参 / 交叉验证
- 和强化学习策略提取主线的正式衔接
- 代码工程化整理

## 4. 现在到底做到了什么地步

### 4.1 已经完成的内容

#### 第一层：能训练出树

`DT/DT-test.py` 和 `DT/datatest814.py` 已经说明：

- 数据可以读入；
- 标签列可以作为分类目标；
- `sklearn.tree.DecisionTreeClassifier` 可以正常训练；
- 可以输出一棵可视化树。

这一步是“可行性验证”。

#### 第二层：已经开始做特征处理

`DT/datatest814.py` 不是直接把全部特征丢进去，而是先计算每个特征和 `动作` 的 Spearman 相关系数，再取前 10 个特征训练。

这说明项目已经从“随便跑一下模型”，往“思考哪些特征更有用”走了。

#### 第三层：已经开始做人工特征工程

`DT/datatest815.py` / `DT/datatest8141.py` 进一步做了两件重要的事：

1. 手工只保留一部分关键列；
2. 新增特征 `速度差 = 己方速度 - 敌方速度`。

这一步很关键，因为它说明你已经不只是“调用现成分类器”，而是在尝试把领域知识放进模型。

#### 第四层：已经开始为“规则提取”做准备

这两份脚本不只是训练和画图，还把树节点信息导出到了表格：

- 父子节点关系
- 划分特征
- 阈值
- 基尼系数
- 样本数
- 预测类别
- 每一类动作在节点中的计数

这非常重要，因为：

**一旦有了节点表，下一步就能进一步自动生成“如果...那么...”规则。**

也就是说，现在已经站到了“规则提取”的门口。

### 4.2 还没完成的内容

虽然已经有不少结果，但从工程和研究角度看，下面这些事情还没真正完成：

1. **代码没有模块化**  
   现在主要还是实验脚本风格，很多逻辑都写在一个文件里。

2. **路径写死**  
   比如多个脚本直接写了 `D:/...` 的绝对路径，可复现性不够。

3. **编码有些混乱**  
   代码里部分中文注释和字符串已经出现乱码痕迹，后续最好统一保存为 UTF-8。

4. **评估还比较初级**  
   目前主要是 `accuracy`，还没有系统比较：
   - precision / recall / F1
   - confusion matrix
   - 各动作类别是否不平衡

5. **没有做系统调参**  
   例如 `max_depth`、`min_samples_split`、`min_samples_leaf`、`criterion` 还没有系统搜索。

6. **没有真正输出“规则文本库”**  
   现在导出了节点表，但还没把根到叶子的路径转换成最终规则。

7. **和强化学习主线还没有完全接通**  
   从仓库内容来看，项目大方向是“强化学习策略提取成决策树”，但目前决策树代码和 RL 轨迹、状态抽取、策略标签生成之间还比较松散。

## 6. 我这次新增的代码是干什么的

新增文件：

- `DT/decision_tree_pipeline_template.py`

它做的事是把现在项目里已经出现过的决策树流程整理成一个更规范的模板，包括：

1. `load_dataset()`  
   读取 Excel 数据。

2. `build_features()`  
   构造输入特征，默认包含：
   - 锁定
   - 我方导弹
   - 敌方导弹
   - 高度差
   - 角度差
   - 距离
   - 速度差

3. `train_model()`  
   划分训练集/测试集并训练树。

4. `evaluate_model()`  
   输出准确率和分类报告。

5. `export_tree_pdf()`  
   导出 DOT 和 PDF。

6. `extract_node_table()`  
   导出节点表。

7. `extract_rules()`  
   从根到叶子自动提取规则路径。

8. `save_outputs()`  
   把节点表和规则表写到文件里。

这个模板的意义不是“最后版本已经完成”，而是：

**它已经把你接下来最该写的结构搭好了。**

## 7. 接下来建议你怎么继续写

我给你一个适合本科生推进的路线，尽量稳，不一下子把题做得太大。

### 第一阶段：把当前实验整理成稳定版本

目标：先让代码稳定、可复现。

要做的事：

1. 把所有绝对路径改成相对路径。
2. 把输入数据路径、输出目录、树深度写成配置参数。
3. 统一编码为 UTF-8。
4. 固定随机种子。
5. 把输出目录统一到比如 `DT/output/`。

完成标志：

- 换一台机器只要数据在仓库里就能跑；
- 不需要手改很多路径。

### 第二阶段：真正做规则提取

目标：把树变成可读规则。

要做的事：

1. 从根节点走到每个叶子节点；
2. 把路径拼成规则文本，例如：

```text
如果 距离 <= 87.24 且 我方导弹 <= 0.5 且 速度差 > 2.17
那么 动作 = 切割拉离机动
```

3. 给每条规则附带：
   - 样本数
   - 预测类别
   - 纯度/基尼系数

完成标志：

- 生成一份 `decision_tree_rules.csv`；
- 每一行都是一条可读规则。

### 第三阶段：做模型评估和对比

目标：知道“这棵树到底好不好”。

要做的事：

1. 增加：
   - confusion matrix
   - precision
   - recall
   - F1-score
2. 比较不同参数：
   - `max_depth`
   - `criterion=gini / entropy`
   - `min_samples_leaf`
3. 比较不同特征方案：
   - 全特征
   - 相关性筛选
   - 手工挑选
   - 手工挑选 + `速度差`

完成标志：

- 有一张对比表，能说明哪种方案最好；
- 不是只看单次 accuracy。

### 第四阶段：和强化学习策略提取主线接起来

目标：让决策树不是孤立分类器，而是 RL 策略解释器。

要做的事：

1. 明确训练样本的来源：
   - 状态是谁生成的；
   - `动作` 标签是不是来自 RL 策略输出。
2. 统一数据处理流程：
   - 轨迹 -> 状态特征 -> 动作标签 -> 决策树训练
3. 比较：
   - 决策树动作
   - 原始 RL 动作
   - 两者在关键状态上的一致性

完成标志：

- 能清楚说出“这棵树是在拟合哪个策略”；
- 决策树结果能回到你的研究主线里。

## 10. 你下一步最推荐先做什么

我建议你优先做这三件事，顺序不要乱：

1. 先用 `DT/decision_tree_pipeline_template.py` 统一流程。
2. 再把规则文本自动导出来。
3. 最后再做参数对比和论文整理。

原因是：

- 没有统一流程，后面改一点就会乱；
- 没有规则文本，就还没真正体现“可解释性”；
- 没有实验对比，最后写报告会比较虚。
