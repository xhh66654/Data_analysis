# 方案文档 vs 项目现状 · 差距分析与优化流程

> **分析对象**：`Algorithm/doc/溯因分析方案.docx`（方案文档 3.2.2 节"智能体溯因技术"）
> **分析目标**：判断现有代码能否满足方案三项技术的需求；若不能，给出完整优化路线。
> **结论先行**：**部分满足（约 35 %）**。方案要求的 3 个子技术，当前仅第 1 个有雏形，第 2、第 3 个几乎缺失，且第 1 个实现与方案差距明显。下面逐项对比。

---

## 一、方案文档要求的 3 项核心技术

| 编号 | 技术名称 | 核心方法 | 应用场景 |
|---|---|---|---|
| **3.2.2.1** | 基于规则抽取的智能溯因技术 | **VIPER 算法**（模仿学习 + 迭代 DAgger）把 RL 策略蒸馏为决策树；提取 IF-THEN 规则集；规则合并与库化 | 海空对抗（10 架蓝方智能体） |
| **3.2.2.2** | 基于博弈约简的智能溯因分析技术 | **结构因果模型 SCM + 平均场** 合并智能体；KL 散度作因果权重；在约简后的多智能体博弈上做溯因 | 红蓝 40 机大规模空战（MARL） |
| **3.2.2.3** | 基于反事实推理的智能溯因分析技术 | **CEMA 模型**：状态回滚 → 前向概率模拟 → 因果效应量（机械论 / 目的论两类解释）→ 自然语言输出 | 红蓝 6 机空战、多目标（击毁率/生存率/暴露风险/弹药…） |

## 二、现状与需求逐条对照

### 2.1 技术 3.2.2.1 — 基于规则抽取（VIPER）

| 方案要求 | 现状 | 差距 |
|---|---|---|
| 量纲规范化 / 离散化预处理 | ✅ `DT/calculate_stats.py`、`normalization_params.csv` 有基础 | 缺"离散化"（方案要求把距离分桶为"远/较远/较近/近/超过"） |
| **VIPER 迭代蒸馏**（DAgger 思想，专家策略与学生决策树交替） | ❌ **未实现**。`DT/datatest8141.py` 只是**一次性**用 `DecisionTreeClassifier.fit` 在静态 Excel 上训练 | **核心算法缺失**。没有"按 π_{i−1} 的状态分布采样 → 并入数据集 → 重训练"的迭代循环 |
| 决策树效能验证（与 RL 模型对抗效能相当） | ❌ 只打印 `accuracy`（动作一致率），未做"对抗回合胜率 / 平均回报"对比 | 缺"决策树 rollout vs RL rollout"的效能回归实验 |
| DFS 遍历决策树生成 IF-THEN 规则集 | ⚠️ **半满足**。只导出了节点表 `decision_tree_nodes3.xlsx`，**没有拼接成完整路径规则** | 需要增加"从根到叶的路径规则字符串化"输出 |
| **规则合并 / 泛化**（去冗余） | ❌ 未实现 | 需实现"条件包含/相似性判断 + 合并" |
| 场景：10 架蓝方智能体、动作空间 0-10（攻击指令） | ❌ 现场景是 `CartPole` / `LunarLander`（单智能体玩具环境） | **场景严重不匹配** |
| 策略规则库 + 博弈策略决策树 | ❌ 未建立 | 需要规则持久化与规则库查询接口 |

**满足度：约 30 %**（有决策树蒸馏的骨架，但 VIPER 核心、规则提取、效能验证、场景均缺）

### 2.3 技术 3.2.2.3 — 基于反事实推理（CEMA）

| 方案要求 | 现状 | 差距 |
|---|---|---|
| **状态回滚到查询动作之前** | ⚠️ `causal/casual-LLV2-1.py` 做了"事实轨迹 + 替换某步动作继续 rollout" | 回滚逻辑较粗糙：直接沿用 `gym env` 的当前状态，**没有 checkpoint / 环境状态快照**机制，所以不能真正 "回滚" 到历史任意时刻；现在它靠"事实轨迹已结束后不能再回滚"躲过去 |
| **前向概率模拟 K 次**（引入扰动，构造多反事实世界） | ❌ 只对每个替代动作**各跑 1 次确定性轨迹**，非方案要求的 "概率模型 / 随机策略 / K 次采样" | 差距大 |
| **奖励向量**（击毁率、生存率、暴露风险、弹药、战术评分） | ❌ 只用**标量** `future_total_reward`（单目标） | 需改为向量化奖励 |
| **机械论解释**（训练模型预测查询是否发生 → 提取特征重要性） | ❌ 完全缺失 | 需实现：用反事实数据集训分类器/特征重要性 |
| **目的论解释**（查询发生样本 vs 未发生样本的奖励向量差排序） | ❌ 完全缺失 | 需实现：按是否出现查询切分，计算 Δreward |
| **自然语言解释生成** | ❌ 当前只打印 "总奖励差"，没有模板化/LLM 化的解释输出 | 需实现模板或接入 LLM |
| 场景：红蓝各 3 机、坐标/速度/航向/弹药/雷达 多维状态；动作含转向/加速/导弹/雷达 | ❌ 当前是 `LunarLander` 玩具环境 | **场景严重不匹配** |

**满足度：约 20 %**（有"替换动作重跑"的雏形，但回滚、随机模拟、向量奖励、两类解释、NLG 全缺）

## 三、完整优化流程（端到端路线图）

建议分 **4 个阶段、6 - 10 周** 完成。顺序上**先补场景 → 再补算法 → 最后补解释层**，每阶段都有可交付物。

### 阶段 0 · 场景与基础设施（1 - 1.5 周）— 补最大短板

> 方案所有技术都围绕**空战/海空对抗多智能体**展开，必须先有这个环境。

1. **选型空战环境**（三选一，推荐第一项）
   - ✅ **推荐**：基于 `pettingzoo` 自研"红蓝多机空战"环境，状态包括坐标/速度/航向/弹药/雷达，动作含 A1-A4（转向/加速/发射/雷达）。
   - 备选 A：接入 `MAgent2`（规模大、易扩展）。
   - 备选 B：使用现成军用仿真（如 HARFANG3D-Sandbox、CloseAirSupport），需协议许可。
2. **环境接口统一化**
   - 提供 `reset(seed)` / `step(actions)` / **`save_checkpoint()` / `load_checkpoint()`**（**关键**，反事实回滚必需）。
   - 状态包含方案表 3 的全部变量（坐标、速度、航向、弹药、雷达）。
3. **基座 RL 训练脚手架**
   - 多智能体版替换 `causal/main.py`，基于 `causal/MADDPG_file/MADDPG.py` 或 `FreeRL-main/.../MAPPO_file/` 改造。
   - 输出：`model/MADDPG_AirCombat_*.pth`、训练曲线、基线胜率。

**交付物**：可多局对打的空战环境 + 一个能稳定收敛的 MARL 基座策略。

---

### 阶段 1 · 完善 3.2.2.1（VIPER 规则抽取）（1.5 - 2 周）

1. **数据预处理模块**（扩展 `DT/calculate_stats.py`）
   - 加入方案要求的**距离离散化**（远/较远/较近/近/超过）。
   - 产出标准化数据集接口 `(X_raw, y)`。
2. **VIPER 迭代蒸馏**（新建 `DT/viper.py`）
   ```
   D = rollout(π_expert, N)                # 初始数据
   tree_0 = CART.fit(D)
   for i in 1..T:
       D_i = rollout(tree_{i-1}, M)        # 按学生策略分布采样
       label D_i with π_expert              # 专家标注
       D = D ∪ D_i
       w_i = loss_upper_bound(D)           # 凸上界加权
       tree_i = CART.fit(D, sample_weight=w_i)
   return best tree on eval return
   ```
3. **决策树效能验证**（新建 `DT/eval_tree_vs_rl.py`）
   - 固定 K 局种子，分别用 RL 策略和决策树策略 rollout，比较：胜率、平均回报、存活步数。
4. **规则提取与合并**（新建 `DT/rule_extract.py`）
   - DFS 遍历 `tree_.children_left/right` 输出路径条件 → `IF ... AND ... THEN action`。
   - 合并逻辑：条件包含检测（区间包含）、同类规则归并、按 support 阈值剪枝。
5. **规则库 & 决策树 API**（新建 `DT/rule_base.py`）
   - `query(state) → rule_id, action, explanation`。

**交付物**：一棵在空战场景上**胜率 ≥ RL 的 90 %** 的决策树 + 结构化规则集（JSON / Excel）+ 查询 API。

---

### 阶段 2 · 完善 3.2.2.3（CEMA 反事实推理）（2 - 2.5 周）

> 先做这个而不是博弈约简，因为它可独立落地、展示效果快，且为 3.2.2.2 打基础。

1. **向量化奖励函数**（在阶段 0 环境里）
   - `R = [kill_rate, survival_rate, exposure_risk, ammo_cost, tactical_score]`。
2. **状态回滚能力**
   - 依赖阶段 0 的 `save_checkpoint / load_checkpoint`。
3. **反事实数据集生成**（方案表 1，新建 `causal/cema/cf_dataset.py`）
   ```
   for k in 1..K:
       env.load_checkpoint(t_query - 1)
       inject_perturbation()              # 扰动敌机/状态
       trajectory_k = rollout(random_policy_or_noisy_π)
       R_k = vector_reward(trajectory_k)
       label_k = 1 if query_event(trajectory_k) else 0
   return D_cf = [(s, a, R, label)]
   ```
4. **因果效应量计算**（方案表 2，新建 `causal/cema/effect.py`）
   - **机械论**：对每个时间切片训练 `f(s_{1:t}) → label`，提 `feature_importance` 排序。
   - **目的论**：按 label 切分 → 计算 `ΔR = mean(R | label=1) − mean(R | label=0)` 并按维度排序。
5. **自然语言解释器**（新建 `causal/cema/nlg.py`）
   - 模板法：`"为什么A不B？因为{top_cause_purpose}，同时{top_cause_mechanism}"`。
   - 或接入小模型（Qwen/DeepSeek 本地）做改写。
6. **替换现有 `casual-LLV2-1.py`** 为新版入口。

**交付物**：对任意 query（如"EGO 为何攻击 Red2 而非 Red1"）输出**两类结构化解释 + 自然语言解释**，效果对标方案表 5/6。

---

### 阶段 3 · 完善 3.2.2.2（博弈约简 SCM）（2 - 3 周）

> 这是工作量最大、学术难度最高的部分。

1. **平均场基座**（新建 `causal/gr/mf_base.py`）
   - 实现 MF 近似的 `Q(s, a, \bar{a}_{-i})`；`\bar{a}_{-i}` 为邻居动作聚合。
2. **SCM 构建**（新建 `causal/gr/scm.py`）
   - 定义外生/内生变量；用结构方程拟合（可用神经网络或线性 SEM）。
   - 用因果发现算法（PC/NOTEARS）从历史轨迹抽因果图。
3. **KL 散度因果权重**（新建 `causal/gr/causal_weight.py`）
   - `w_ij = KL(π_i(·|s) || π_i(·|s, do(a_j = null)))`。
4. **智能体合并**
   - 按 `w_ij` 选 top-k 邻居 → 聚合为"虚拟对手"。
   - 其他智能体降权/冻结。
5. **约简后再跑 CEMA**
   - 把阶段 2 的 CEMA 跑在约简图上，对比解释长度 / 可读性提升。
6. **反向解释模型**（新建 `causal/gr/abductive.py`）
   - 用注意力网络 `g(s, history, neighbor_actions) → explanation_factor`。

**交付物**：约简前后的**对比实验**——约简后溯因解释的平均长度、用户偏好（人工评估）显著优于约简前，且策略效能损失 < 5 %。

## 四、关键风险与注意事项

| 风险 | 缓解措施 |
|---|---|
| 空战环境自研成本高，易延期 | 先用**简化版**（6 机对抗、离散动作），充分满足方案表 3/4；后期再扩展 40 机 |
| VIPER 中"专家标注 D_i"需要反复调用 RL 模型，速度慢 | 批处理 + 预计算 Q 值缓存 |
| 状态回滚（checkpoint）在复杂物理引擎中不可靠 | **强约束**：环境从一开始就要求是"状态可序列化"的（`dict` 化而非 C++ 指针） |
| SCM 因果发现对数据量敏感，效果不稳定 | 先用**领域先验手工画 DAG**，再数据驱动微调 |
| NLG 解释自然度差 | 先模板法保底；若资源允许接入本地 LLM（Qwen-7B 等）做润色 |
| 评估缺少 ground-truth | 引入**人工评估**（3-5 人打分）+ **一致性指标**（规则-动作一致率、解释-专家共识率） |
